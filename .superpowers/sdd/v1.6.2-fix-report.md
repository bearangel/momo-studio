## 实施摘要

### 核心算法（`electron/src/main/skill/zip-uploader.ts`）

`uploadSkillZip(buffer, filename)` 返回类型 breaking change：`{ slug, description }` → `UploadedSkill[]`。

**三种模式识别 + slug 决策**：

| 模式 | SKILL.md 路径 | slug 来源 | 收集的 entry |
|---|---|---|---|
| A 扁平 | `SKILL.md`（根目录） | `frontmatter.name` 转 kebab → 否则 filename 去 `.zip` | 全部非元数据 entry |
| B 包裹 | `<slug>/SKILL.md` | 子目录名（frontmatter.name 不覆盖） | `<slug>/` 前缀下 entry |
| C 批量 | 多个 `<slug>/SKILL.md` | 各自子目录名 | 每个 skill 各自的 `<slug>/` 前缀下 entry |

**OS 元数据忽略**（`isIgnoredEntry`）：`__MACOSX/` 整目录前缀 + 逐段检查 `.DS_Store` / `Thumbs.db` / `._*`（AppleDouble）/ `*.bak` 后缀。

**SHA256 幂等**：整个 zip buffer 取一次 hash，批量场景下所有 skill 共享（因为是同一个 zip）。每个 skill 独立判断：同 hash 跳过 / 不同 hash 备份旧目录后覆盖。

**路径防御三层**（全部保留）：① entryName 含 `..` 跳过 ② rel 为空或含 `..` 跳过 ③ resolved path 必须在 targetDir 沙箱内。

**slug 合法性**：空串 / 含 `..` / 含 `/` / 含 `\` → 抛 `非法 slug`。

**深度规则**：SKILL.md 路径 ≤ 2 段合法；`a/b/SKILL.md` 抛 `路径过深`。

## 三种模式的算法说明

```
uploadSkillZip(buffer, filename):
  1. 列出全部 SKILL.md entry（过滤 OS 元数据后）
     - 路径 == 'SKILL.md' 或 endswith '/SKILL.md'
     - 过滤掉 isIgnoredEntry（__MACOSX/ / .DS_Store / ._ / Thumbs.db / .bak）
  2. 空 → 抛 'zip 内未找到 SKILL.md'
  3. hash = SHA256(整个 buffer)  # 批量场景共享
  4. for each skillEntry:
     a. 校验深度：split('/') > 2 段 → 抛 '路径过深'
     b. 解析 frontmatter → name + description
     c. 推断 slug：
        - 2 段 → slug = parts[0]（子目录名）
        - 1 段（根目录）→ slug = nameToSlug(name) || filename.replace('.zip$')
     d. slug 合法性校验
     e. SHA256 幂等：同 hash → skipped=true
     f. 非 skip：
        - 备份 + 清理旧目录
        - 解压：扁平收集全部 entry / 包裹收集 <slug>/ 前缀
        - 三层路径防御
        - 写 .sha256 标记
     g. results.push({ slug, name: name||slug, description })
  5. return results
```

### 2. 三种模式的边界用例覆盖完整？

- 模式 A：name 转 kebab / filename 兜底 / 资源文件 / 空 filename

### 3. __MACOSX 忽略是否破坏现有内置 skill 假设？

✅ 不破坏。内置 skill（builtin）从 `resources/skills/` 目录扫描，不走 zip-uploader 路径（`resolveBuiltinSkillsDir` 独立）。marketplace 安装走 `installer.ts`，也不经过 `uploadSkillZip`。只有 custom zip 上传走新逻辑。v1.5 git-tools / code-review 等内置 skill 完全不受影响。

### 4. slug 决策优先级清晰？

✅ 清晰：
- 模式 B/C（子目录）：slug = 子目录名，**frontmatter.name 不覆盖**（避免 zip 内 frontmatter 与目录名不一致时产生歧义）
- 模式 A（扁平）：`frontmatter.name` 转 kebab → 否则 `filename` 去 `.zip` → 否则抛错（空 slug）
- 全模式最后做合法性校验（`..` / `/` / `\` / 空串）

### 5. 路径防御三层保留？

✅ 完整保留，且新增 OS 元数据过滤作为第 0 层：
- 第 0 层（新）：`isIgnoredEntry` 过滤 OS 元数据
- 第 1 层：`entryName.includes('..')` 跳过
- 第 2 层：`rel` 为空或含 `..` 跳过
- 第 3 层：`resolvedDest` 必须在 `resolvedTarget` 沙箱内

## Concerns

1. **混合 zip（根 SKILL.md + 子目录 SKILL.md）**：算法独立处理每个 SKILL.md，扁平 skill 会收集全部 entry（含子目录）。非典型场景，未明确禁止。如需严格模式隔离可后续加校验。
2. **批量场景的 SHA256 共享**：所有 skill 共享整个 zip 的 hash。这意味着如果 zip 内容有 ANY 变化（即使只改了一个 skill），所有 skill 都会判定为"不同 hash"并覆盖。这是设计选择（简单），不是 bug——批量重新上传本就应全量覆盖。
3. **filename 大小写**：扁平模式 filename 兜底时保留原大小写（`MySkill.zip` → slug `MySkill`）。如需统一小写可后续加 `toLowerCase()`，但当前尊重用户命名。
