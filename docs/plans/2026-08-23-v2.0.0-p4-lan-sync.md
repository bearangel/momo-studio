# 2.0.0 P4「局域网联网」实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在既有 P2P 层（mDNS 发现/信任/TCP 直连/签名验签，P1 已接线）之上实现 spec §7：任务看板只读镜像广播 + 资源分享（agent/MCP）与一键导入。

**Architecture:** P2pSync 从单一 message 类型泛化为多类型分发（快照/目录/请求/供给四种新 payload）；出站采用「事件触发全量快照」策略（信任节点少、数据量小，简单可靠）；入站远端数据一律**内存缓存不落库**（远端任务绝不写 tasks 表——防本节点调度器误捡；远端资源经请求-供给协议按需拉取完整定义后落地为 custom）。

**Tech Stack:** 既有 P2P 栈（bonjour + net + Ed25519），零新增依赖。

**上游 spec:** `docs/specs/2026-08-23-v2.0.0-platform-refactor-design.md` §7（联网）、决策 D6（局域网优先）/D7（看板只读）。
**范围裁定（控制器，写入交付说明）:** ① skill 的 P2P 分享留 2.1（需文件块传输协议；agent/MCP 是 JSON 结构化定义可载）；② 任务广播用全量快照（不做增量 diff）；③ 远端任务 UI 轮询刷新（5s，同 NodeDiscoveryPanel 模式，不加推送通道）。

## Global Constraints

- Node 20（`export PATH=/home/ai-agent/.nvm/versions/node/v20.20.2/bin:$PATH`）；pnpm `npx pnpm@9.0.0`。
- TypeScript strict：禁止 `any` / `@ts-ignore` / `as any`。注释中文；Conventional Commits。
- **只读镜像铁律**：远端任务/资源入站数据只进内存缓存；`tasks` 表与调度器绝不消费远端数据（spec D7）。
- 广播容错沿用现有策略：单节点失败不阻塞（`.catch(() => {})` 遍历信任节点）。
- P2P 层既有测试（router/sync/integration-wiring）不得回归。

### Task 1: P2P 协议扩展——payload 类型泛化 + P2pSync 多路分发

**Files:**

**Interfaces:**
- Produces:
  - `MessagePayload['type']`: `'message' | 'task-snapshot' | 'resource-catalog' | 'resource-request' | 'resource-provide'`（原 'task'|'presence'|'ack' 预留位收敛为上述五个实义值——grep 确认无生产发送方后改枚举；注释说明 2.1 可再扩 presence/ack）

  - `interface ResourceCatalogEntry { nodeId: string; nodeName: string; items: Array<{ type: 'agent'|'mcp'; slug: string; name: string; description: string; version?: string }>; takenAt: number }`
  - `P2pSyncOpts` 扩展：`onRemoteTaskSnapshot?: (snap: TaskSnapshot, fromNodeId: string) => void`；`onRemoteResourceCatalog?: (cat: ResourceCatalogEntry, fromNodeId: string) => void`；`onResourceRequest?: (req: { requestId: string; resourceType: 'agent'|'mcp'; slug: string }, fromNodeId: string) => void`；`onResourceProvide?: (prov: { requestId: string; definition: Record<string, unknown> } , fromNodeId: string) => void`
  - `P2pSync` 方法：`broadcastTaskSnapshot(snap)` / `broadcastResourceCatalog(cat)` / `sendResourceRequest(targetNodeId, req)` / `sendResourceProvide(targetNodeId, prov)`——全部遍历信任节点（send 类单发指定节点）
  - 现有 `broadcastNewMessage`/`onRemoteMessage` 行为不变

## 风险与缓解

- **双机联调不可行（容器单机）**：T2-T5 全部以单进程单测 + mock router/transport 覆盖协议正确性；真机演示（spec 验收 6「两台局域网设备互信」）留 macOS 主机——计划如实声明。
- **快照风暴**：事件触发全量广播在多节点高频写时可能放大流量——信任节点数个位数量级 + 任务量百级以内，帧体积 KB 级，可接受；2.1 若需增量再做。
- **slug 碰撞**：p2p 资源 id 含 nodeId 前缀 + 导入 slug 加后缀，双保险。
- **skill 排除的 UI 一致性**：目录构建侧排除（远端 skill 根本不出现），无需 UI 特判。
