# v2.5.0 变更账本与撤销实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI 工具层文件变更全量记账（journal + content-addressed 快照），hash 守卫的安全撤销（含交叉逆序语义），git 多仓探测器兜 bash 洞，配额滚动清理。

**Architecture:** 新 `journal/` 模块（store/recorder/revert/detector/quota + IPC）；记账点单点收口在 FileTools 写类操作 + ApplyPatchTools 落盘前；blob 落 userData 内容寻址去重，条目入 state.db（migration v33）；UI 两入口（消息流 chip + 任务卡审查面板）。

**Tech Stack:** Electron 主进程（CommonJS）+ better-sqlite3 + React renderer。无新 npm 依赖。

**Spec:** `docs/specs/2026-09-10-change-journal-undo-design.md`（D1-D7 以 spec 为准）

**计划对 spec 的一处精化（实现裁定，非偏离语义）**：spec §5.2 的 `message_id` 列**取消**——消息行在流结束才落库，记账时该 id 不存在；归组键统一用 `stream_session_id`（UI 经既有 streamSessionId→message 反查模式定位消息，AgentStreamBubble.tsx:112-118 同款）。`session_id` 取 `ctx.roomId`（v2 会话 id 经此透传，运行时验证）。

### Task 3: revert 核心（hash 守卫 + 逆序 + 对称记账）

**Files:**

**Interfaces:**
- Consumes: Task 1/2
- Produces:
  - `type RevertOutcome = { id: string; path: string; result: 'reverted' | 'skipped-diverged' | 'restored-missing' | 'no-op' | 'failed'; detail?: string }`
  - `revertEntries(workspaceId: string, workspaceDir: string, ids: string[], opts: { force?: boolean; recorderCtx?: RecordCtx }): Promise<RevertOutcome[]>`——按 path 分组后组内 created_at 逆序逐条执行；每次写回前对称记账（op 取逆操作：create↔delete、modify↔modify、rename↔rename 反向）

- [ ] **Step 1: 失败测试（每分支专项——spec §8）**

```typescript
// 真实临时 workspace 目录 fixture。断言清单：
// 1) modify 正常撤回：hash(after) 匹配 → 写回 before，文件内容断言
// 2) create 撤回 → 文件删除
// 3) delete 撤回 → 重建 before 内容（restored-missing 场景单独测：文件已不存在 → 重建）
// 4) rename 撤回 → 移回 old_path（目标已存在叠加警告 detail）
// 5) hash 漂移：记账后手动改文件 → 默认 skipped-diverged；force=true → 写回 before
// 6) 交叉逆序：A、B 两 modify 同文件，revertEntries([A,B]) → B 先 A 后（文件终态 = A.before）；
//    revertEntries([A]) 单撤 A → skipped-diverged
// 7) 孤儿条目：记账后未写盘（before==当前）→ no-op
// 8) 对称记账：每次撤回产生逆条目（listByPath 计数 +1），撤销的撤销可再执行
// 9) 失败传播：writeFile 抛错 → failed，不中断同文件后续条目？——设计裁定：组内遇 failed 即停该文件，返回已执行部分
```

- [ ] **Step 2: 实现 revert.ts**（文件操作用 `node:fs/promises`；rename 目标存在时 detail 警告但继续）
