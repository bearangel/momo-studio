# v2.6.0 任务断点续跑实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 重启后 in-flight 任务经启动恢复卡确认，从 message_events 重建回合状态、从中断点继续执行（已完成工具不重跑）。

**Architecture:** 不新建持久化——`message_events` 即断点真相源。三新单元：`turn-reconstructor.ts`（事件→LLMMessage 聚合，孤儿 tool_call 合成中断 result）、`task/resume.ts`（启动检测+恢复编排，经既有 executor 派发）、`ResumeNotice.tsx`（恢复卡，v2.5 账本联动）。`runChatLoop` 加 `resumeTurn?` 可选参数。**两处既有行为修正**：steer drain 补事件落库；正常退出时任务不再被 failTaskOnCrash 误标 failed（关机保态）。

**Tech Stack:** Electron 主进程 + better-sqlite3 + React。无 migration、无新表、无新依赖。

**Spec:** `docs/specs/2026-09-10-task-resume-design.md`（D1-D6 以 spec 为准）

**计划补强的三处实现裁定**（planning 期发现，spec 风险区落地）：
1. **关机保态**：现状 `before-quit → destroyAllTaskDrivenRuntimes → handleChildExit → failTaskOnCrash` 把 in_progress 任务标 failed——正常退出被误记为失败。修法：runner 加 `markShuttingDown()`，关机路径先置 flag，`handleChildExit` 据此跳过任务终态转换（保留 in_progress）但保留 `finalizeStreamOnCrash`（消息行标 failed，UI 诚实呈现中断）；恢复时把消息行翻回 streaming。
2. **steer 事件落库**：现状 drain 只进内存 messages 不落事件——重建器看不到。修法：drain 时补发 `{type:'steer', streamSessionId, body}` chunk 走既有 event buffer 落库；重建器消费；renderer 聚合器对未知类型已跳过（实现时验证，未跳过则聚合器加 skip 分支）。
3. **断点流 id 定位**：不migration 加列。恢复时经任务执行会话的**车道串行性**（v2.3 lane：同会话同时仅一活跃流）取该会话最新带 streamSessionId 的消息行即断点回合。

### Task 1: turn-reconstructor 重建器（纯核心）

**Files:**

**Interfaces:**

- Produces:

  - 孤儿 tool_call 合成文案（常量导出）：`[执行中断：进程重启，该工具未完成或结果未知。请自行判断是否重试]`

- [ ] **Step 1: 失败测试（九场景矩阵）**

```typescript
// electron/tests/agent/turn-reconstructor.test.ts
// fixture：真实 db（global-defaults 模式）+ 手插 message_events 行——行形状必须照抄
// stream-relay.ts 的落库字段（先读它；含 message_id/seq/event kind/payload JSON）。
// 九场景（每场景独立 it）：
// 1. 完整回合：user 起始(经 message 行) + assistant 文本(text_delta 累积) + 1 对 tool_call/tool_result
//    → messages = [user, assistant(toolCalls), tool(result), assistant(text)]；toolCallsUsed=1
// 2. 孤儿 tool_call（有 call 无 result，含 dispatch 形态 toolName 前缀）→ tool 消息 = 合成文案
// 3. 半截 assistant 文本（text_delta 无 end）→ 收尾为完整 assistant 消息
// 4. degenerate：仅 start + user，无任何 assistant 事件 → degenerate=true, messages 仅 [user]
// 5. assigned 无事件：查无事件 → degenerate=true, messages=[]
// 6. steer 已 drain（含 steer 事件）→ 该 steer 随 [用户中途补充] user 消息重建
// 7. steer 未 drain（steer 事件在末尾之后无输出）→ 进 steers[] 数组
// 8. 未知事件类型（插一行 kind='future_thing'）→ 跳过不炸
// 9. 重建抛错（插一行 payload 非法 JSON 但 repo 不抛时用 monkeypatch repo 抛）→ 降级 degenerate
// 附：seq 乱序插入（先插 seq 大再插小）→ 按 seq 排序聚合
```

- [ ] **Step 2: 实现**（聚合算法：按 seq 排序 → 状态机累积 text_delta 为当前 assistant 缓冲 → tool_call 开新 pending 对（可多个并发 call）→ tool_result 按 callId 配对 → 流末 flush：残留 text 缓冲收尾 + 未配对 call 合成 result；user 起始消息从 messages 表按 streamSessionId 取该流的消息行 body——**实现首步探明 messages 行与流的关联字段**）
