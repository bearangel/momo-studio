# v2.8.0 Orchestration 元语 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 子 agent 续接（dispatch_followup，replay 重建）+ 异步派发族（dispatch_bg / gather / status / cancel）——5 个新编排原语，零新表零迁移。

**Architecture:** followup 从 message_events 重建链历史（复用 v2.6 turn-reconstructor 聚合语义）经 `TaskConfig.historyPrefix` 前缀拼接；bg 句柄表（内存 Map，上限 8）+ gatherWaiters 唤醒 + `handleTaskReply` 单点收口扩展；路由链 routeDispatch 与同步 dispatch 零改动。

**Tech Stack:** 纯 TypeScript（dispatch-wait.ts / runtime-entry.ts / runtime-config.ts / 新 sub-history-reconstructor.ts）。无新依赖。

**Spec:** `docs/specs/2026-09-12-orchestration-primitives-design.md`——实现疑义以 spec 为准。

### Task 1: 子会话重建器（sub-history-reconstructor）

**Files:**
- Create: `electron/src/main/agent/sub-history-reconstructor.ts`
- Test: `electron/tests/agent/sub-history-reconstructor.test.ts`

**Interfaces:**
- Consumes: `turn-reconstructor.ts` 的 `INTERRUPTED_TOOL_RESULT` 常量与事件聚合语义（**import 共享不复制**）；storage 层 `listEventsByMessage` / messages 查询（先读 `electron/src/main/storage/messages/repo.ts` 确认既有查询函数，缺则在本模块内写 SQL）
- Produces:
```typescript
export interface RebuiltSubHistory {
  messages: import('./llm-provider').LLMMessage[];  // 不含 system
  rounds: number;               // 追问轮次统计（首轮 dispatch + N 次 followup）
  degraded: boolean;            // 任何重建异常 → true + messages=[]
}
export function rebuildSubConversation(taskId: string, executionSessionId: string): RebuiltSubHistory;
```

- [ ] **Step 1: 写失败测试**（真 SQLite tmp 库插消息 + message_events，同 turn-reconstructor.test.ts fixture 模式）：
  - 两轮链 verbatim：首轮 assistant 开头（dispatch 指令不落消息行——transient 桥；LLM 可从上下文推断）+ 第二轮 followup（user 消息为追问文本）→ messages 含两轮全部 assistant/tool 对
  - 孤儿 tool_call（中断轮）合成 `[执行中断]` tool result
  - 会话过滤：task_id 相同但 session 不同（伪造行）不进重建
  - 空链（无消息）→ `{messages:[],rounds:0,degraded:true}`
  - 重建抛错（monkeypatch 查询函数 throw）→ degraded 兜底不抛
- [ ] **Step 2: 确认 FAIL**（模块不存在）
- [ ] **Step 3: 实现**——要点：
  - 查询：`SELECT id, role, content, parent_stream_session_id, created_at FROM messages WHERE task_id = ? AND session_id = ? ORDER BY created_at ASC`（列名以实际 schema 为准，先核对 messages 表列）
  - 每消息 `listEventsByMessage(id)` 聚合（与 rebuildTurn 同构：text_delta 拼接 / tool_call+tool_result 配对 / 孤儿合成中断 result）
  - 跨消息轮次拼接 + rounds 统计（子链内 user 角色消息数 = followup 轮数）
  - **首轮指令不回溯**：dispatch 首轮 body 不落消息行且内部事件桥 transient——重建链恒以 assistant 开头（合法，LLM 从上下文自推断）；不造合成 user 消息
  - catch 全包 → degraded
- [ ] **Step 4: 全绿 + Commit**：`feat(orchestration): 子会话重建器——链历史 replay + 孤儿合成 + 降级`
