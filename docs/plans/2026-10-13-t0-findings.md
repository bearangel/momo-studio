# T0 插桩复现判定记录——子 agent 中断失效断点裁决

- 日期：2026-10-13
- 任务：P0-B 首任务（spec `2026-10-13-dispatch-receipt-and-interrupt-cascade-design.md` §7.4）
- 复现 harness：`electron/tests/agent/interrupt-cascade-e2e.test.ts`（3 用例：场景 1 绿 / 场景 2 机制绿 / T0 红点 `it.fails`）
- 病理样本：会话 spring-mcp（d2163577）——PM 停止后 researcher 子流运行 22 分钟至自然完成

---

## 0. 裁决总表

| 假设 | 表述 | 裁决 | 关键证据 |
|---|---|---|---|
| **H1** | routeAbortDispatch 广播的 subStreamSessionId 与子 runner activeTasks 键不匹配（routeDispatch 侧 ID 回收再生成） | **不成立** | 代码五点同源 + harness 场景 1 绿（ID 全链对齐断言通过） |
| **H2** | abort 消息到达子进程，但 chat loop 仅取消当前 LLM fetch，工具循环不检查 abort 标志 | **不成立**（强形式） | chat loop 三检查点 + LLM fetch 全程 signal 感知 + 既有回归锁；仅 MCP 工具有弱残留（见 §3） |
| **H3** | 该链为 dispatch_bg 派发（fire-and-forget，PM 中止根本不产生 abort_dispatch） | **成立（命中）** | 生产 DB 实证 `dispatch_bg:researcher` + harness 场景 2 复现（零 abort_dispatch / 零广播 / registry 恒 in_flight） |

**一句话结论：22 分钟病理 = H3。** spring-mcp 的 PM 用 `dispatch_bg:researcher` 派发 researcher；PM 流 16:27:34 被停止时，bg 链没有任何 abort 联动（`executeDispatchBg` 无 signal 参数，唯一取消入口是 PM 主动调 `dispatch_cancel` 工具——PM 进程已随中止退出），子 agent 从未收到任何中断信号，自然跑完 22 分钟。

## 3. H2 裁决：不成立（强形式）；MCP 工具有弱残留

### 3.1 chat loop abort 检查点清单（`runtime-entry.ts` runChatLoop）

| 检查点 | 位置 | 语义 |
|---|---|---|
| abortListener（IPC 入口） | `:1062-1067` | `{type:'abort'}` 按 streamSessionId 精确匹配 → `abortController.abort()` |
| LLM fetch | `:1320` | `chatStream(messages, tools, abortController.signal)`——建连/退避/流读取全程可中断（`llm-provider.ts:150-208` signal 组合 + `:863-875` buildAbortPromise：**signal 已 abort 时立即 reject**——abort 后的下一轮 LLM 调用不可能发出） |
| dispatch 批次后 | `:1733` | `if (abortController.signal.aborted \|\| settled.some(rejected))` → `(中断)` + end(interrupted) 退出 |
| 工具错误 | `:1795-1806` | AbortError 或 signal.aborted → 立即跳出 chat loop（防中断-重试死循环） |
| 长工具 signal 透传 | `:2263-2264`（bash/webfetch）、`:2296`（同步 dispatch）、`:2377`（gather） | 执行中工具即时响应停止 |

### 3.2 既有回归锁

`dispatch-parallel.test.ts:423-459`「并发批次中断」：两成员 dispatch 批次执行中注入 abort → 断言 `result === '(中断)'`、无 tool_result 回填、`end.finishReason === 'interrupted'`——**真实 runChatLoop 在执行中收到 abort 会终止**已被锁定。

### 3.3 弱残留（不构成 22 分钟病理，记录备查）

- **MCP 工具调用不感知 signal**：`runtime-entry.ts:2445` `requestMcpCall(config.workspaceId, mcpName, toolName, args)` 无 signal 参数——MCP 调用在途时 abort 需等其自然返回，loop 才在下一检查点退出。修法（若未来需要）：requestMcpCall 增加 signal 透传。低优先级。
- 成功返回的工具与下一轮 LLM 调用之间无显式 `signal.aborted` 检查——但下一轮 `chatStream` 对已 abort 的 signal 立即 reject（§3.1 第 2 行），等效于检查点。22 分钟 = 数十轮 LLM 调用，若 H2 成立不可能全部忽略 signal。

### 3.4 生产数据反证

researcher 终态 `done`（自然完成）而非 `aborted/interrupted`——「收到 abort 但 loop 忽略」的流会以 interrupted 收尾。且 §1.2 已证该链根本无 abort 生产者。

## 4. H3 裁决：成立（命中）——22 分钟病理的完整机理

### 4.1 代码链：bg 链零 abort 联动

- `dispatch-wait.ts:766-800` `executeDispatchBg`：**签名无 signal 参数**，不注册 waitForTaskReply（无 onAbort → 不发 abort_dispatch）；句柄只进 PM 子进程内存 `bgHandles`（`:789-796`）。
- PM 中止路径：主进程 `abortStreamBySessionId(pmSsi)` → PM runner `abortStream` → PM 子进程 `abortController.abort()` → PM chat loop 退出 → **PM 进程内 bgHandles 与一切等待态蒸发**。主进程 `dispatchRegistry` 的链条保持 `in_flight`，无人对其调用 `cancel()`。
- 唯一取消入口：PM 主动调 `dispatch_cancel` 工具（`executeCancel` → `buildAbortDispatchMessage` → 广播）——PM 已死，永不发生。
- 对照（同步链为什么没事）：`executeDispatch(..., signal)`（`dispatch-wait.ts:424`）→ PM abort 触发 `waitForTaskReply.onAbort`（`:358-388`）→ `sendAbortDispatchEvent` → `routeAbortDispatch` 广播 → 子流中止（§2 全链完好）。

### 4.2 连锁症状（与 spec §1 P-2/P-3 互证）

- 16:29:41 PM 唤醒回合 `dispatch_gather` 报「句柄不存在」——bgHandles 是 PM 子进程内存态，跨进程/跨回话蒸发；主进程 registry 才是跨回合真相源（v2.9 已建）但 gather 不查它。
- researcher 22 分钟后终态 → 迟到 task_reply → registry settle（done/未投递）→ PM 空闲补投——正是「打地鼠」回执循环的输入之一。

### 4.3 harness 复现（场景 2，绿机制记录 + it.fails 红点）

同一 PM 回合双链对照（bg + 同步）：中止 PM 后——

| 观察 | 同步链 | bg 链 |
|---|---|---|
| abort_dispatch 事件 | ✅ 产生 | ❌ **零** |
| 子壳收到 {type:'abort'} | ✅ ≤2s | ❌ **500ms 观察窗零**（且无任何异步生产者） |
| registry 终态 | cancelled | **恒 in_flight** |

红点用例（`it.fails`）：「T0 红点：中止 PM 流后 dispatch_bg 子 agent 流应 ≤2s aborted（spec §11.3-11）」——当前实现下 `vi.waitFor` 2s 超时于断言 `subChildAborts.some(↔bg 流 id) === true`（expected false to be true），**红在正确的断言上**（已临时摘除 it.fails 验证失败点，验证后恢复）。B3 修复落地后该用例转绿 → `it.fails` 报「expected to fail but passed」→ 摘除 `.fails` 即转正回归锁。
