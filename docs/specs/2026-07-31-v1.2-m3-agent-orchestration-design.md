# v1.2 M3：主/子 Agent 编排设计

> **版本**：v1.2.0（M3）
> **日期**：2026-07-31
> **状态**：已确认，待编写实施计划
> **依赖**：v1.1.1（M2）已合并 main

## 1. 背景与问题

v1.1.1 测试发现：runtime 与 IPC 层已声明了主→子 dispatch 协议（`assignMainAgent` + `dispatch:<slug>` 动态工具），但存在两个层面的缺口：

1. **Runtime bug**：`assignMainAgent` 构造了 `subAgents` 数组但未传入 `spawnAgent`（`ipc.handlers.ts:134-156`）；`auto-start.ts:81` 硬编码 `subAgents: []`。即使 IPC 被调用，main agent 也永远拿不到 dispatch 工具。
2. **UI 缺口**：创建/编辑表单不能选择角色（standalone/main/sub）和父 agent；AgentList 没有主子关系展示；没有编排入口。

当前所有经"添加 agent"创建的 agent 均为 standalone，无 dispatch 工具，协调 agent 无法把任务派给专项 agent。

## 2. 方案选择

**方案 B：完整编排编辑器**——Agent 面板内"列表/编排"视图切换，编排视图以树形展示 main→sub 层级，支持关系操作（添加子 / 解除 / 设为主）。

不使用拖拽（agent 数量少，按钮操作更可发现、更易测试）。

## 3. Runtime 修复层

三个必须修复的 bug，否则 UI 无法工作。

### R1：assignMainAgent 传递 subAgents

**位置**：`electron/src/main/agent/ipc.handlers.ts:134-156`

`assignMainAgent` 在 125-128 行构造了 `subAgents: SubAgentRef[]`，但 `spawnAgent` 调用（循环体 134-156）未传入此参数。

**修法**：main 实例的 spawn 调用增加 `subAgents` 字段：

```typescript
spawnAgent({
  // ...现有参数...
  agentType: def.type,
  subAgents: def.type === 'main' ? subAgents : [],
  // ...
});
```

### R2：auto-start 重建 subAgents

**位置**：`electron/src/main/agent/auto-start.ts:81`

当前硬编码 `subAgents: []`，应用重启后 main agent 的 dispatch 能力丢失。

**修法**：遍历 workspace 下全部 assignments，为每个 main 从 DB 重建 `SubAgentRef[]`：

```typescript
// 伪代码
const wsAssignments = listAssignmentsByWorkspace(workspaceId);
for (const assignment of wsAssignments) {
  const def = getAgentDefinition(assignment.agentDefinitionId);
  if (def.type === 'main') {
    const subAssignments = wsAssignments
      .filter(a => {
        const subDef = getAgentDefinition(a.agentDefinitionId);
        return subDef.parentAgentId === def.id;
      })
      .map(a => {
        const subDef = getAgentDefinition(a.agentDefinitionId);
        return { slug: subDef.slug, botUserId: a.botMatrixUserId, description: subDef.description };
      });
    spawnAgent({ ..., agentType: 'main', subAgents: subAssignments });
  } else {
    spawnAgent({ ..., agentType: def.type, subAgents: [] });
  }
}
```

### R3：createFromYaml slug→UUID 解析

**位置**：`electron/src/main/agent/ipc.handlers.ts:302-307`

`createFromYaml` 直接保存 `parseAgentManifest` 返回值，其中 `parentAgentId` 是 slug 字符串。但 `assignMainAgent` 按 UUID 匹配（`d.parentAgentId === mainDef.id`），导致 YAML 创建的 sub agent 无法被正确识别。

**修法**：`createFromYaml` 保存前查找 parent slug → UUID（复用 `builtin.ts` 的两阶段解析逻辑）。

### 验证标准

- 通过 `assignMain` 安装 main + subs 后，main 的 LLM 工具列表包含 `dispatch:<sub-slug>`
- 应用重启后，已安装的 main 仍然有 dispatch 工具
- YAML `parentAgentId: pm-agent` 创建后 DB 存的是 pm-agent 的 UUID

## 4. IPC 扩展层

### 4.1 createCustom 扩展

```typescript
interface CreateCustomInput {
  // ...现有字段...
  type?: 'standalone' | 'main' | 'sub';   // 默认 standalone
  parentAgentId?: string;                   // 仅 type='sub' 时有效
}
```

主进程校验（`agent:createCustom` handler）：

- `type='sub'` 时 `parentAgentId` 必填，且 parent 必须存在且 `type='main'`
- `type='standalone'` 或 `type='main'` 时清除 `parentAgentId`（强制 undefined）
- 禁止 self-parent（`parentAgentId === def.id`）
- 禁止循环引用（parent 链不能指回自己）

### 4.2 updateDefinition 扩展

```typescript
interface UpdateDefinitionInput {
  // ...现有字段...
  type?: 'standalone' | 'main' | 'sub';
  parentAgentId?: string;
}
```

同 4.1 校验规则。额外处理：

- 改角色/父 agent 时自动调 `stopRunningInstancesByDefinition(id)`
- 如果原 main 被改为 standalone/sub 且有 subs → 拒绝，提示"请先解除所有子 agent 的关联"
- `crud.ts` UPDATE SQL 增加 `type` 和 `parent_agent_id` 两列

### 4.3 AssignMainInput 扩展

```typescript
interface AssignMainInput {
  workspaceId: string;
  mainDefId: string;
  llmApiKey: string;
  selectedSubDefIds?: string[];  // 要安装的子 agent 定义 ID（undefined = 全部）
}
```

`assignMainAgent` 内部：`const subDefs = allSubDefs.filter(d => !selectedSubDefIds || selectedSubDefIds.includes(d.id))`

### 4.4 角色编辑安全矩阵

| 操作 | 条件 | 处理 |
|---|---|---|
| main → standalone | 有 subs | 拒绝"请先解除子 agent 关联" |
| main → standalone | 无 subs | 允许，停止实例 |
| standalone → main | — | 允许 |
| standalone → sub（指定 parent） | — | 允许，停止实例 |
| sub → standalone | — | 允许，停止实例，清除 parentAgentId |
| sub parent A → parent B | — | 允许，停止实例 |

## 5. 移除级联

当前 `removeAgentAssignment` 已让 bot 离开房间 + 清 assignment（commit `56c2c75`）。需补充：

| 操作 | 级联 |
|---|---|
| 移除 main assignment | 同时移除同 workspace 内所有 `parentAgentId === mainDef.id` 的 sub assignments（bots 也离开房间） |
| 移除 sub assignment | 仅移除该 sub；main 的 subAgents 在重启后自动缩减（auto-start 重建时不再包含）；main 正在运行时需停止后重启以更新 dispatch 工具列表 |

## 6. 编排编辑器 UI

### 6.1 视图切换

Agent 面板顶部加 `[列表] [编排]` 切换按钮。默认显示列表视图（现有 AgentList）。视图状态不持久化。

### 6.2 编排视图 — 树形结构

```
📋 PM Agent                 [main] ▸
  ├── 🔗 需求分析师   ●运行中  [解除]
  └── 🔗 程序员       ●运行中  [解除]
  [+ 添加子 agent]

🤖 独立助手                 [standalone]
  [设为主 agent]

📋 调度员                   [main] ▸
  └── 🔗 测试员     ○已停止  [解除]
  [+ 添加子 agent]
```

**节点类型**：

| 角色 | 图标 | 标签 | 可折叠 |
|---|---|---|---|
| main | 📋 | `[main]` | 是 |
| sub | 🔗 | 运行状态 + `[解除]` | 否 |
| standalone | 🤖 | `[standalone]` | 否 |

**节点操作**：

| 节点 | 操作 | 行为 |
|---|---|---|
| main | `[+ 添加子 agent]` | 弹出选择器，列出 workspace 内所有可成为子的 agent（standalone + 未关联 sub 定义），选中后 `updateDefinition({ type: 'sub', parentAgentId })` |
| main | 折叠/展开 | 收起/展开子节点 |
| sub | `[解除]` | 确认后 `updateDefinition({ type: 'standalone', parentAgentId: undefined })` |
| standalone | `[设为主 agent]` | 直接 `updateDefinition({ type: 'main' })` |

### 6.3 AgentList 角色徽标

列表视图增加角色感知：

- 每个agent 项左侧角色图标（📋/🔗/🤖）
- sub agent 缩进显示在其 main 下方
- 保留现有运行状态、协调徽标、编辑/停止操作

## 7. AddAgentDialog 增强

### 7.1 选择已有定义 — main 展开子勾选

选中 `type='main'` 的定义时，表单动态展开子 agent 勾选区（默认全选）。提交时调 `assignMain({ workspaceId, mainDefId, llmApiKey, selectedSubDefIds })`。

standalone/sub 定义按现有流程走 `addToWorkspace`（sub 定义单独添加时作为独立实例运行，无 dispatch 能力）。

### 7.2 创建自定义 — 角色选择

创建表单增加角色下拉（独立/主/子）。选"子"时显示父 agent 下拉（只列 main 定义）。无 main 定义时禁用"子"选项。

### 7.3 编辑已有定义 — 角色可改

编辑模式复用创建表单。角色和父 agent 可编辑，保存时触发 §4.4 安全校验和实例停止。

## 8. 边界条件

| 场景 | 处理 |
|---|---|
| main 的某个 sub 未安装 | subAgents 只含已安装的 sub；main 无法 dispatch 到未安装的 sub |
| 重复安装同一 main | 拒绝：检查 mainDef 是否已有 assignment，提示"已安装，请先移除" |
| main 同时是 coordinator | 互不冲突：`isCoordinator` 控制团队群接待，`agentType='main'` 控制 dispatch 能力 |
| 解除父子关系时 sub 正在运行 | `updateDefinition` 触发 `stopRunningInstancesByDefinition`，提示重启 |
| 编排视图只展示已安装 agent | 纯定义（未 assignment）不出现在编排视图，只在 AddAgentDialog 定义列表可见 |
