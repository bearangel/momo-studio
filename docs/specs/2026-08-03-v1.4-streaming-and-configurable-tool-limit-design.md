# v1.4 设计：流式回复 + 可配置工具调用上限

> 状态：草案
> 日期：2026-08-03
> 范围：agent 会话体验优化——流式回复（含 thinking / 工具调用展示）+ 工具调用上限可配置

## 1. 目标与痛点

### 痛点

1. **无流式反馈**——agent 响应过程中用户完全不知道发生了什么，只能干等。最终一次性返回全部内容。
2. **thinking 不可见**——支持推理的模型（OpenAI o 系列 / Anthropic thinking）其思考过程被丢弃。
3. **工具调用不可见**——用户看不到 agent 调了哪些工具、结果是什么，过程是黑盒。
4. **工具上限硬编码**——`MAX_TOOL_ROUNDS = 10` 不可配置，复杂任务（编程）不够用。

### 目标

- agent 回复实时流式呈现：thinking（默认折叠）+ 工具调用卡片 + 正文逐字流式
- 工具调用上限可配置：全局默认 + 房间级覆盖 + per-task 重置 + 0-无限范围
- 用户可在 agent 响应中插入新消息（中断当前响应，开始新任务）
- 提供停止按钮

## 2. 核心概念

### 「会话」= 房间 + per-task 预算

- 房间（Matrix room）有独立的 `maxToolCalls` 配置
- 用户每发一条消息 = 一个新任务（task）→ 预算池重置
- 所有参与响应的 agent（main + sub）共享同一预算池
- agent 通过 system prompt 得知预算上限，自行规划工具使用

### 工具调用上限值语义

| 值 | 含义 |
|---|---|
| `0` | 禁用所有工具调用（纯对话模式，不给 LLM 工具列表） |
| `N`（正整数） | 最多 N 次工具调用 |
| `-1` | 无限制 |

## 3. 架构设计

### 3.1 流式传输：双通道（IPC 实时 + Matrix 持久化）

```
用户发消息 (m.room.message + @mention)
      │
      ▼
 Matrix /sync ──→ agent 子进程收到消息
                       │
                       ▼
                 runChatLoop() 改造：
                 ┌──────────────────────────────┐
                 │ 1. 创建 streamSessionId       │
                 │ 2. 调 llm.chatStream()        │
                 │ 3. 每收到 delta →             │
                 │    process.send(chunk)        │
                 │ 4. 工具执行 →                 │
                 │    process.send(toolEvent)    │
                 │ 5. 循环直到 finishReason      │
                 │    = stop 或预算耗尽          │
                 └──────────────────────────────┘
                       │
                ┌──────┴───────┐
                │              │
         process.send()    最终 Matrix
         (实时流式 chunk)   m.room.message
                │              │
                ▼              ▼
         主进程             Matrix /sync
         runtime-manager     (持久化)
         转发 →              │
         webContents.send()  │
                │              │
                ▼              ▼
         Renderer IPC     Renderer Matrix
         (实时流式 UI)     (最终替换流式)
```

**为什么不用纯 Matrix 流式（m.replace 编辑）：**
- Matrix /sync 轮询间隔 1-3s，用户感知不流畅
- Conduwuit/Tuwunel 可能对高频编辑限流
- thinking 和工具调用结构化数据塞进 event content 复杂

**为什么需要 Matrix 持久化：**
- 刷新/切换房间后历史完整
- Matrix 仍是消息持久化层，IPC 只是实时传输层

### 3.2 streamSessionId 机制

每次 `runChatLoop()` 生成一个 UUID。所有 IPC chunk 和最终 Matrix 消息都带这个 ID。

- renderer 用它把流式片段聚合到同一个临时消息气泡
- Matrix 最终消息到达后，renderer 用 Matrix 版本替换临时版本

### 3.3 共享工具预算：主 agent 管理制

dispatch 是同步阻塞的（main 等 sub 回复）。流程：

1. Main agent 已用 X 次工具（含 dispatch 这次本身 = X+1）
2. dispatch 消息携带 `tool_budget = maxToolCalls - (X+1)`
3. Sub agent 收到，用这个预算跑自己的 `runChatLoop`
4. Sub 的 task_reply 携带 `tool_calls_used = N`
5. Main 收到回复后 `budgetRemaining -= N`

无需跨进程 IPC 同步预算——dispatch/task_reply 已有的消息通道顺带传递预算信息。

### 3.4 中断重置（Interrupt）

用户在 agent 流式响应中发新消息 = 中断当前任务，开始新任务：

1. Renderer 发 `ipc.agent.abortStream(roomId)` → 主进程
2. 主进程查 `activeStreams.get(roomId)` → 子进程发 `{ type:'abort', streamSessionId }`
3. 子进程 `AbortController.abort()` → LLM fetch 抛 AbortError
4. 子进程发 `end(interrupted)` chunk → 退出 `runChatLoop`
5. 主进程清理 activeStreams，创建新 StreamSession（新预算）
6. 新消息触发新 `runChatLoop`

中断后：
- 部分回复保留在 UI（底部栏标注「已中断」）
- 预算重置——中断 = 放弃旧任务，新任务自带新预算

### 3.5 停止按钮

与中断相同的 abort 机制，但不发新消息。用户点停止 → agent 停止生成 → 部分回复保留。

## 5. LLM Provider 流式接口

### 5.1 新增类型

```typescript
/** 流式 delta（从 SSE stream 归一化） */
type StreamDelta =
  | { type: 'thinking'; content: string }
  | { type: 'text'; content: string }
  | { type: 'tool_use'; toolCall: LLMToolCall }
  | { type: 'done'; finishReason: 'stop' | 'tool_use' };

interface LLMProvider {
  // 保留旧接口（测试/回退用）
  chat(messages: LLMMessage[], tools?: LLMToolDef[]): Promise<LLMResponse>;
  // 新流式接口
  chatStream(
    messages: LLMMessage[],
    tools: LLMToolDef[] | undefined,
    signal: AbortSignal,
  ): AsyncIterable<StreamDelta>;
}
```

### 5.2 OpenAI 兼容（`stream: true`）

SSE 解析：
- `choices[0].delta.reasoning_content` → thinking delta（o 系列 / deepseek-reasoner）
- `choices[0].delta.content` → text delta
- `choices[0].delta.tool_calls` → 累积为完整 tool_use（按 index 合并 arguments JSON fragment）
- `choices[0].finish_reason` = `"tool_calls"` | `"stop"` → done

### 5.3 Anthropic（`stream: true`）

SSE 解析：
- `content_block_delta` + `delta.type = "thinking_delta"` → thinking delta
- `content_block_delta` + `delta.type = "text_delta"` → text delta
- `content_block_start` + `content_block.type = "tool_use"` → 开始累积 tool_use
- `content_block_delta` + `delta.type = "input_json_delta"` → 追加到 tool arguments
- `message_stop` → done

Anthropic thinking 需在请求体加：
```json
{ "thinking": { "type": "enabled", "budget_tokens": 10000 } }
```

### 5.4 非流式降级

部分 provider 不支持 SSE。如果 `chatStream` 首次请求返回非 `text/event-stream`（HTTP 200 但 Content-Type 不匹配），自动降级到 `chat()` 一次性返回，然后发出一个 `text` delta + `done`。

### 5.5 Thinking 支持

| 平台 | 字段 | 条件 |
|---|---|---|
| OpenAI o 系列 | `delta.reasoning_content` | 模型支持（o1/o3/deepseek-reasoner） |
| Anthropic | `thinking` content block | 请求体加 `thinking: { type: "enabled", budget_tokens: N }` |
| 不支持的模型 | 字段不存在 | 正常流式文本，UI 不显示 thinking 折叠区 |

## 6. Runtime 改造

### 6.1 IPC Chunk 类型

```typescript
type StreamChunk =
  | { type: 'start'; streamSessionId: string; roomId: string; botUserId: string }
  | { type: 'thinking'; streamSessionId: string; delta: string }
  | { type: 'text'; streamSessionId: string; delta: string }
  | { type: 'tool_call'; streamSessionId: string; toolName: string; args: Record<string, unknown> }
  | { type: 'tool_result'; streamSessionId: string; toolName: string; result: string; success: boolean }
  | { type: 'end'; streamSessionId: string; finishReason: 'stop' | 'budget_exhausted' | 'interrupted' | 'error'; error?: string };
```

### 6.2 runChatLoop 重写

```
async runChatLoop(client, roomId, userMessage, config, ctx, session):
  streamSessionId = session.streamSessionId
  // -1（无限）映射为 Infinity，避免 budgetRemaining 递减为负数
  budgetRemaining = session.maxToolCalls === -1 ? Infinity : session.maxToolCalls
  abortController = new AbortController()

  messages = [system, ...history, { role:'user', content:userMessage }]

  // 注入预算提示
  budgetHint = formatBudgetHint(session.maxToolCalls)
  if budgetHint: messages[0].content += budgetHint

  send({ type:'start', streamSessionId, roomId, botUserId })

  for round = 0; ; round++:
    tools = (budgetRemaining == 0) ? undefined : ctx.tools

    accumulatedText = ""
    accumulatedThinking = ""
    toolCalls = []

    for delta in llm.chatStream(messages, tools, abortController.signal):
      switch delta.type:
        case 'thinking':
          accumulatedThinking += delta.content
          send({ type:'thinking', streamSessionId, delta: delta.content })

        case 'text':
          accumulatedText += delta.content
          send({ type:'text', streamSessionId, delta: delta.content })

        case 'tool_use':
          toolCalls.push(delta.toolCall)

        case 'done':
          if finishReason == 'stop':
            // LLM 认为完成了
            send({ type:'end', streamSessionId, finishReason:'stop' })
            // 发最终 Matrix 消息（含 thinking + tool_calls 持久化数据）
            await sendFinalMatrixMessage(...)
            return accumulatedText

    // finishReason == 'tool_use' → 执行工具
    if toolCalls.length > 0:
      if budgetRemaining == 0:
        // 理论上不该到达（tools=undefined 时 LLM 不应返回 tool_use）
        send({ type:'end', finishReason:'error', error:'预算为0但LLM返回tool_use' })
        return

      messages.push({ role:'assistant', content: accumulatedText, toolCalls })

      for tc in toolCalls:
        if budgetRemaining == 0 and session.maxToolCalls > 0:
          // 预算耗尽
          send({ type:'end', finishReason:'budget_exhausted' })
          await sendFinalMatrixMessage(...)
          return

        // dispatch 工具特殊处理：传剩余预算
        if tc.name.startsWith('dispatch:'):
          // Infinity 无法 JSON 序列化，用 -1 表示无限
          dispatchContent.tool_budget = (budgetRemaining === Infinity) ? -1 : budgetRemaining - 1

        send({ type:'tool_call', streamSessionId, toolName: tc.name, args: tc.arguments })
        result = executeTool(tc, ...)
        send({ type:'tool_result', ..., success, result })

        budgetRemaining--

        // dispatch 回来后扣减 sub 使用的量
        if tc.name.startsWith('dispatch:'):
          budgetRemaining -= reply.tool_calls_used

        messages.push({ role:'tool', content: result, toolCallId: tc.id })

      // 继续循环（LLM 可能还要调更多工具）
      continue
```

### 6.3 预算提示注入

system prompt 追加（让 LLM 感知预算）：

```
## 工具调用预算
本任务工具调用上限：10 次（所有参与 agent 共享此预算）。
请合理规划工具使用，避免不必要的重复调用。
```

值格式：
- `0`：`本任务禁止使用任何工具。`
- `N`：`本任务工具调用上限：N 次（所有参与 agent 共享此预算）。`
- `-1`：不注入（无限制）

### 6.4 最终 Matrix 消息

任务完成后照常发 `m.room.message`，content 嵌入持久化字段：

```json
{
  "msgtype": "m.text",
  "body": "最终完整回复文本",
  "io.momo-studio.stream_session_id": "uuid",
  "io.momo-studio.thinking": "思考过程全文",
  "io.momo-studio.tool_calls": [
```

renderer 加载历史时，如果消息含这些字段，渲染增强版气泡（thinking 折叠 + 工具卡片）。

### 6.5 Abort 机制

**主进程：**
```typescript
// runtime-manager 维护
const activeStreams = new Map<roomId, { streamSessionId: string; child: ChildProcess }>();

// 用户中断/停止时
function abortStream(roomId: string): void {
  const entry = activeStreams.get(roomId);
  if (entry) {
    entry.child.send({ type: 'abort', streamSessionId: entry.streamSessionId });
  }
}
```

**子进程：**
```typescript
// 监听 abort IPC
process.on('message', (msg) => {
  if (msg.type === 'abort' && msg.streamSessionId === currentSessionId) {
    abortController.abort();
  }
});

// runChatLoop 内 catch
try {
  for await (const delta of llm.chatStream(..., abortController.signal)) { ... }
} catch (err) {
  if (err.name === 'AbortError') {
    send({ type:'end', streamSessionId, finishReason:'interrupted' });
    return;
  }
  throw err;
}
```

### 8.4 ThinkingSection 交互

- 默认折叠——不干扰正文阅读
- 有 thinking 内容时显示折叠头（`💭 思考过程`），点击展开
- 无 thinking 时（模型不支持）整个组件不渲染
- 流式过程中 thinking 也可展开

### 8.5 ToolCallChip 交互

- 流式过程中默认展开（用户需要看到正在执行什么）
- 任务完成后默认收起（紧凑展示）
- 紧凑行：状态图标 + 工具名 + 参数摘要 + 耗时
- 点击切换展开参数/结果详情
- 状态：`⏳ 执行中` → `✓ 完成(120ms)` / `✗ 失败`

### 8.6 历史消息增强

从 Matrix 加载的消息，如果 content 含 `io.momo-studio.thinking` 或 `io.momo-studio.tool_calls`，渲染增强版气泡（复用 ThinkingSection + ToolCallChip），但不显示流式状态/停止按钮。

### 8.7 流式 → 持久化替换

1. 流式中：renderer 维护临时 `Map<streamSessionId, StreamState>`
2. Matrix 最终消息到达（含 `io.momo-studio.stream_session_id`）
3. renderer 用 Matrix 消息替换临时状态（从 Map 删除）
4. 闪烁光标消失，底部栏变为「✓ 已完成」

竞态处理：如果 Matrix 消息先于 `end` chunk 到达，renderer 直接替换，忽略后续 `end` chunk。

## 10. 错误处理

| 场景 | 处理 | 用户可见 |
|---|---|---|
| LLM 流式中网络断开 | catch → `end(error)` → Matrix 错误消息 | `⚠️ 出错：网络断开` |
| LLM 超时（5min） | AbortSignal.timeout → 同上 | `⚠️ 出错：请求超时` |
| 工具执行失败 | 不中断流式——错误文本回传 LLM 自我纠正 | ToolCallChip `✗ 失败` |
| 预算耗尽 LLM 还想调工具 | 停止 chat loop → `end(budget_exhausted)` | `⚠️ 预算耗尽` |
| 用户中断 | abort IPC → `end(interrupted)` | `⏹ 已中断`，部分回复保留 |
| 子进程崩溃 | `child.on('exit')` → `end(error)` → renderer 清理 | `⚠️ Agent 进程异常退出` |
| Renderer 刷新 | 临时状态丢失——Matrix 最终消息到达后自然出现 | 无中断感 |
| Provider 不支持 SSE | 降级 `chat()` → 单次 text delta + done | 完整回复（无打字效果） |
| 流式与 Matrix 竞态 | Matrix 消息先到 → renderer 替换临时状态，忽略后续 end | 无可见异常 |
