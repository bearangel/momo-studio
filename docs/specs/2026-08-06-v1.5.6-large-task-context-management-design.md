# v1.5.6 — 大任务上下文管理优化

**版本**：v1.5.6
**作者**：Sisyphus
**日期**：2026-08-06
**状态**：已实施

## 1. 背景

v1.5.5 解决了 PDU 截断丢失 dispatches + sendEvent 失败死循环的紧急 bug，但用户进一步问"如何支持全代码 review / 超大模块连续编写"场景。对比 opencode/Claude Code 后发现三个核心差距：

1. **read_file 一次性返回整个文件**：LLM 调一次 read_file 就把整个大文件塞进 LLM 上下文，多次累积爆模型上下文上限
2. **长回复无分段机制**：LLM 单次回复超 ~3KB 就有 PDU 截断风险
3. **持久化 PDU 强制截断**：thinking/tool_calls/todos 超 55KB 时被 4-5 级截断丢失
4. **无主动上下文管理**：长任务多轮对话累积必爆
5. **PM 不会主动 dispatch 拆任务**：所有工作都自己做

## 2. 目标

让 Momo Studio 能稳定支持"全代码 review / 超大模块连续编写"场景。

## 3. 实施（5 大改动）

### 3.1 read_file 分页（file-tools.ts）

**新参数**：`offset`（1-based，默认 1）+ `limit`（默认 2000，上限 5000）

**尾部提示**：还有更多行 → `\n...(共 N 行，已显示 M-K 行；用 offset=K+1 继续读取)`

**测试**：6 用例（分页 / 默认 / 超界 / 末尾 / 上限保护 / 兼容）

### 3.2 task_complete 主动分段（runtime-entry.ts）

**工具**：`task_complete(summary, nextStep?)` — LLM 主动分段持久化

**执行**：内联 chat loop（不走 ToolModule）：
- 持久化当前段为独立 Matrix 消息（sessionId 加 `#segN` 后缀）
- 重置 accumulatedText/Thinking
- chat loop 不退出，LLM 继续
- MAX_TASK_SEGMENTS=5 防滥用

### 3.3 compact 上下文压缩（runtime-entry.ts）

**工具**：`compact(summary)` — LLM 主动压缩对话历史

**执行**：内联 chat loop：
- summary < 50 字符拒绝（防滥用清空上下文）
- 重置 messages = [system, {role: user, content: `[历史对话总结]\n${summary}`}]
- chat loop 继续，LLM 基于总结工作

### 3.4 持久化分层（agent-meta.ts + IPC + sendFinalMessage + IPC handler）

**Migration v14**：`agent_meta` 表（meta_id, thinking, tool_calls, todos, created_at）

**混合策略**（5KB 阈值）：
- thinking + toolCalls JSON + todos JSON ≤ 5KB → 直接放 Matrix event（兼容旧渲染）
- \> 5KB → 子进程 IPC 请求主进程写入 SQLite → Matrix event 只存 `agent_meta_id`

**IPC**：
- 子进程 → 主进程：`agent:writeMeta`（child IPC 模式，跟 settings:resolveMaxToolCalls 一致）
- renderer → 主进程：`agent:getMeta`（Electron ipcMain.handle）

**降级**：IPC 失败/超时 → 全字段入 Matrix（原路径，向后兼容）

### 3.5 PM 自动 dispatch 教学（runtime-entry.ts:formatDispatchHint）

**注入条件**：`config.role === 'main' && config.subAgents.length > 0`

**教学内容**：
- 可用 sub agent 列表 + 各自 slug + description
- 主动拆分原则：≥3 文件 / 多模块 / 可并行 → dispatch
- 长任务自身管理：compact / task_complete / read_file offset

## 4. 关键设计决策

### 4.1 read_file 默认 2000 行
跟 opencode 标准对齐。典型 LLM 上下文 8K-32K tokens，2000 行代码约 5K-15K tokens。

### 4.2 task_complete / compact 不走 ToolModule
两者需访问 chat loop 内部状态（accumulatedText / messages / segmentCount），无法通过 ToolContext 暴露。内联处理最简洁。

### 4.3 持久化分层 5KB 阈值
- 小消息（绝大多数）继续放 Matrix event，无 IPC 开销
- 大消息（罕见）才分层，避免 PDU 截断
- 5KB 留充足预算给 body + dispatches + 其他元数据

### 4.4 compact summary 最小 50 字符
防 LLM 滥用清空上下文（"ok" 之类无效 summary 会让 LLM 失忆）。

### 4.5 dispatch 教学 prompt 而非硬编码规则
PM 拆任务是智能决策，硬编码规则（如"文件数 > 3 时 dispatch"）过于僵化。teach prompt 让 LLM 自己判断，更灵活。
