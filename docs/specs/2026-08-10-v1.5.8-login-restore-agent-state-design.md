# v1.5.8 — 登录后恢复上次 agent 运行状态

## 背景

v1.5.7 引入 token 过期自动跳转登录页 + 退出登录流程后，用户反馈：**重新登录后所有 agent 全部下线，必须逐个手动上线**。

## 根因

| 时机 | 调用 `startSyncFromSession` | 调用 `autoStartAgents` |
|---|---|---|
| App 启动（已有 session） | ✅ `autoRestoreSession` (`index.ts:56-58`) | ✅ 同上 |
| `auth:register` | ❌ handler 只调 `registerFlow + persistSession` | ❌ |
| `auth:login` | ❌ 同上 | ❌ |
| `auth:logout` | ✅ `stopSync` | — |

`auth:login` IPC handler 成功后既不重启用户 Matrix sync、也不调用 `autoStartAgents`。Renderer 把 status 改成 authenticated 跳进主界面，但主进程的 sync client / agent runtime 都没启动 → UI 显示全部离线。

## 用户需求

**精确记忆上次每个 agent 的 on/off 状态**：用户在 Session 1 手动下线的 agent，重新登录后保持下线；只有"用户上次意图为运行"的 agent 才自动恢复。

## 设计

### 数据模型（Migration v15）

```sql
ALTER TABLE agent_assignments ADD COLUMN last_running INTEGER NOT NULL DEFAULT 1;
```

| 字段 | 含义 | 写入时机 |
|---|---|---|
| `enabled` (现有) | assignment 是否存在（未删除） | 创建 assignment 时设 1；未来软删除走 0 |
| `last_running` (新增) | 用户最近的运行意图 | `spawnAgent` → 1；`stopAgent`（手动）→ 0；崩溃/退出不改 |

**两字段独立维度**：`autoStartAgents` 查询 `WHERE enabled=1 AND last_running=1`。

**存量数据**：默认值 1 → 老用户升级后首次登录所有 agent 全部启动（符合现有期望，无 surprise）。

### 主进程代码改动

**1. `auth.handlers.ts` — 登录/注册后触发恢复**

```typescript
ipcMain.handle('auth:login', async (_evt, opts) => {
  const result = await loginFlow(opts, deps);
  await startSyncFromSession();
  await autoStartAgents();
  broadcastRuntimeChanged();
  return result;
});
```

- `auth:register` 同（新用户无 agent 时 no-op）
- `auth:logout` 不动 `agent_assignments.last_running`（保留用户意图）

**2. `runtime-manager.ts` — `spawnAgent`/`stopAgent` 写 DB**

- `spawnAgent`：spawn 前 `UPDATE ... SET last_running=1`（DB 失败只 warn 不抛）
- `stopAgent`：kill 前 `UPDATE ... SET last_running=0`（DB 失败只 warn 不抛）

**3. `auto-start.ts` — 查询条件改**

```typescript
'SELECT * FROM agent_assignments WHERE enabled = 1 AND last_running = 1'
```

### 数据流验证

| 场景 | 预期行为 |
|---|---|
| 首次注册新用户 | autoStartAgents 查 0 条 → no-op；后续分配 agent 时 spawnAgent 写 last_running=1 |
| 手动下线后重新登录（核心） | Session 1 下线 B（写 last_running=0）；重新登录只启动 last_running=1 的 A、C |
| 手动下线后应用重启 | 走 `app.whenReady` → `autoRestoreSession` → `autoStartAgents`，行为同上 |
| agent 子进程崩溃 | exit handler 自动重启，不调 stopAgent，last_running 保持 1 |

### 错误处理

| 失败点 | 行为 |
|---|---|
| `loginFlow` 失败 | 抛出，handler 不调 startSync/autoStart，用户留在登录页 |
| `startSyncFromSession` 失败 | catch + log，不阻塞 autoStartAgents |
| `autoStartAgents` 整体失败 | catch + log，不阻塞登录 |
| 单 agent token 丢失 | per-agent try/catch 已存在，跳过 |
| `UPDATE last_running` 失败 | warn 日志，不阻塞 spawn/stop |

### 测试策略

1. **migration v15**：字段存在 + 默认值 1
2. **`auto-start.test.ts`**：last_running=0 不启动；=1 启动
3. **`runtime-manager.test.ts`**：spawn/stop 后 DB 状态正确；DB 写失败不抛
4. **`authFlows.test.ts`**：login/register 成功后 startSync + autoStart 被调用

### 范围外

- `auth:logout` 是否 `stopAllAgents`：另一个独立 bug，单独修
- `before-quit` 是否写 last_running=0：不需要（last_running 是用户意图，退出不改意图）
- 多用户切换：当前架构单用户

## v1.5.8 补丁：bot token 预验证

### 问题

v1.5.8 主功能上线后，用户报告重新登录后 3 个 agent 启动失败：

```
M_UNKNOWN_TOKEN: Unknown access token.
[agent:xxx] Fatal: Matrix sync 失败
[agent:xxx] exit code 1
```

每个 agent 走崩溃重启 3 次后放弃，浪费 ~5s 并产生大量噪声日志。

### 根因

`autoStartAgents` 从 keychain 取 bot token 后直接 spawn 子进程，**不在主进程层验证 token 是否被服务端认可**。bot token 失效场景：
- Conduwuit 数据被清/重启换 DB
- token 被 Matrix 服务器主动撤销
- keychain 残留旧环境 token
- bot 账号被用户在服务端删除

### 修复

`auto-start.ts` 加 `verifyBotToken(botUserId, token)` 函数：
- 用 bot token 创建临时 matrix client（`createMatrixClient`）
- 调用 `client.whoami()`——轻量认证探测端点，单次往返即得 401/200 答案
- 失败则 catch + 返回 `{ok:false, reason}`，不抛

spawn 前 token 验证：
- ok=true → 走原 spawn 流程
- ok=false → 跳过该 agent + warn 日志（含 botUserId / slug / reason / tokenPrefix 前 8 字符 / hint），不进入子进程崩溃循环

### 设计取舍

- **不自动重新注册 bot 账号**：bot 注册用一次性随机 password（不存），账号一旦 token 失效就永久不可恢复。自动注册新 bot 需要：分配新 bot_matrix_user_id + 更新 assignment + 重新邀请进所有房间 + 更新 main agent 的 subAgents 列表——复杂度大，留作 v1.5.9。
- **不删 stale keychain entry**：保留原 token（可能后续有诊断价值），让用户在 UI 删除 agent 时统一清理。
- **不向 renderer 报告**：当前只在主进程日志报告；UI 提示需要新增 IPC 通道 + agent 状态扩展，留作后续。

### 测试覆盖

新增 3 测试到 `auto-start-last-running.test.ts`：
- whoami 成功 → spawn
- whoami 抛 M_UNKNOWN_TOKEN → 跳过 spawn
- 混合：valid 启动，invalid 跳过（按 botUserId 路由 mock，不依赖 SQL 顺序）

总计 v1.5.8：electron +19 测试（migration v15 + last_running + auth handlers + token 预验证）。
