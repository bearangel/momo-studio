# v1.6 — Agent 能力配置 + Marketplace 自定义上传设计

**版本**：v1.6.0
**作者**：Sisyphus（基于 brainstorming 会话产出）
**日期**：2026-08-11
**状态**：已实施（v1.6.0）

## 1. 背景

v1.5 之前，agent 的能力（工具 / MCP / Skill）配置存在三处断裂：

1. **关键 bug**：`spawn-helpers.ts:163-164` 的 `buildSpawnOpts` 把 `mergeCapabilities` 的 `merged.tools` 字段**完全丢弃**——只传 `skills` 和 `mcpNames`，没传 `allowedTools`。后果是 `RuntimeConfig.allowedTools` 永远 undefined，`permission.ts:24` 走空数组分支全放行，**所有 agent 实际能用全部 24 个工具**，能力白名单形同虚设。
2. **UI 缺编辑器**：`DefinitionEditor.tsx` 自定义 agent 表单只有 name/slug/prompt/icon/provider/model/scope，**完全没有** `defaultTools / defaultMcps / defaultSkills` 编辑入口。用户即使想限制能力也无从下手。
3. **Marketplace 无自定义入口**：只能浏览远程 catalog + install。后端 `mcp:register` IPC 早已存在，但 UI 没按钮调用它；Skill 也没有"上传/注册自定义"入口。

v1.5 工具库扩充到 24 个工具后，能力配置断裂的影响被放大——agent 默认能跑任意 shell、commit 任意文件、调用任意 MCP 工具，安全护栏与最小权限原则完全失效。

v1.6 系统性补齐能力配置能力：修复 bug + 加 UI + 加 Marketplace 自定义入口 + 加 per-assignment override 让 builtin agent 也可精细调整。

## 2. 目标

- 修复 `merged.tools` 丢失 bug，让 `RuntimeConfig.allowedTools` 真正生效
- `DefinitionEditor` 增加 defaultTools / defaultMcps / defaultSkills 编辑 UI（Tab + 类别分组 checkbox）
- 新建 custom agent 时默认勾选"安全最小集"（read/write/list/edit/grep/glob/todowrite + dispatch-if-main）
- Builtin agent 通过 Layer 3 per-assignment override 实现能力增/减
- `AddToWorkspaceDialog` 与 `WorkspaceAgentsPanel` 提供 Layer 3 override UI
- Marketplace 顶部增加"+ 添加 MCP"和"+ 上传 Skill"按钮，支持表单式注册自定义 MCP 与 zip 包上传 Skill
- 已注册自定义 MCP / 已上传 Skill 可删除

## 3. 非目标

- 不实现 MCP 远程 URL 拉取（仅 stdio command + args + env 表单式注册，v1.7 考虑）
- 不实现 Skill 远程 URL 下载（仅本地 zip 包上传，与 marketplace install 路径合流）
- 不实现 builtin agent 直接编辑 default* 字段（builtin 仍是只读，靠 Layer 3 override）
- 不实现 MCP 鉴权（env 变量加密）—— v1.6 env 明文存 SQLite（与 v1.5 行为一致）
- 不实现 Marketplace 包签名验证（v2.0 任务）
- 不实现 MCP HTTP/SSE transport（v2.0 任务）
- 不重写 CapabilityConfig 现有 Layer 2 UI（仅增强按钮入口）

## 4. 关键决策汇总

| 维度 | 决策 | 理由 |
|---|---|---|
| 范围 | 完整三件套：bug 修复 + DefinitionEditor 加能力编辑器 + Marketplace 加自定义入口 | 一个版本交付完整功能，避免半成品 |
| Builtin 能力调整 | Layer 3 per-assignment override（add+remove delta） | builtin 本体不可改，但同一 agent 在不同 ws 实例化时能力可增减 |
| Layer 3 语义 | 加/减双 delta（added[] + removed[]） | 比"完全替换"灵活，比"仅黑名单"完整，UI 三态 checkbox 直观 |
| MCP 注册形态 | 表单式（name + version + command + args[] + env{}） | 后端 mcp:register IPC 已实现，UI 仅包装；stdio 全场景覆盖 |
| Skill 上传格式 | .zip 包（v1.6.2 起支持三种结构：扁平 `SKILL.md` / 包裹 `<slug>/SKILL.md` / 批量多个 `<slug>/`） | 与 marketplace install 走相同 loader 路径，SHA256 校验幂等；自动忽略 macOS/Windows 元数据 |
| 能力选择 UI | Tab + 类别分组 checkbox | 24 个工具按文件/搜索/Shell/Git/Web/Todo/LSP 分组清晰 |
| 新 agent 默认 | 安全最小集（read/write/list/edit/grep/glob/todowrite + main 加 dispatch） | 默认安全；用户主动加 bash/git_commit 等高危工具 |
| 自定义入口位置 | Marketplace 顶部按钮（与 catalog 同页） | 用户习惯到 Marketplace 找资源 |
| builtin 默认工具修复 | Migration v16 把 builtin 的 default_tools 强制写为 v1.5 全部 24 个工具 | 保证升级后 builtin 行为不变，不出现"突然不能 bash"回归 |

## 5. 架构总览

### 5.1 三层能力合并模型（已有 + 本期扩展）

```
Layer 1  AgentDefinition.default*       ← builtin YAML / custom def 自带（已有字段）
   ∪
Layer 2  WorkspaceAllocation            ← workspace 共享（已有表 workspace_allocations）
   ∪
Layer 3  AssignmentCapabilityDelta      ← 【新增】per-assignment 加/减 delta
   -
   = 最终 merged 清单 → 注入 RuntimeConfig.allowedTools / mcpNames / skills
```

### 5.2 DB Schema 改动（Migration v16）

新增 1 张表（不动现有表）：

```sql
CREATE TABLE IF NOT EXISTS agent_assignment_capabilities (
  assignment_id   TEXT NOT NULL REFERENCES agent_assignments(instance_id) ON DELETE CASCADE,
  capability_type TEXT NOT NULL CHECK (capability_type IN ('tool','mcp','skill')),
  mode            TEXT NOT NULL CHECK (mode IN ('add','remove')),
  ref             TEXT NOT NULL,
  PRIMARY KEY (assignment_id, capability_type, mode, ref)
);
```

`mcp_definitions` 表加 2 列：

```sql
ALTER TABLE mcp_definitions ADD COLUMN source      TEXT NOT NULL DEFAULT 'marketplace';
ALTER TABLE mcp_definitions ADD COLUMN installed_at TEXT NOT NULL DEFAULT (datetime('now'));
```

**设计要点**：
- 复合主键保证幂等
- `ON DELETE CASCADE`：assignment 删除时 delta 自动清理
- `(assignment_id, capability_type, ref)` 在两个 mode 中可能各一条；合并算法处理顺序：先 union add，再 subtract remove（同 ref 同时出现在两侧时 remove 胜出）
- `mcp_definitions.source` 区分 marketplace 装的（不可删）与用户注册的（可删）

### 5.3 Builtin 默认工具修复（关键安全网）

**问题**：v1.5 builtin YAML 各 agent 的 `defaultTools` 字段参差不齐——空数组会让 builtin agent 完全不受限（permission.ts 空 = 全放行）。修复 merged.tools bug 后，builtin agent 行为会**不可预测地变化**。

**Migration v16 数据修复**：

```sql
UPDATE agent_definitions
SET default_tools = ?
WHERE source = 'builtin';
```

JSON 内容 = v1.5 全部 24 个工具的 ToolRef 数组。结果：
- v1.5 用户升级到 v1.6：builtin agent 行为**不变**（仍 24 个工具全开）
- 用户想限制 builtin：通过 Layer 3 override 显式 `removed`
- custom agent：默认"安全最小集"，不受影响

### 5.4 关键 bug 修复（spawn-helpers.ts）

### 5.5 三层合并函数（capability-merger.ts 改造）

```typescript
export interface AssignmentDeltas {
  addedTools: string[];   removedTools: string[];
  addedMcps: string[];    removedMcps: string[];
  addedSkills: string[];  removedSkills: string[];
}

export function mergeCapabilities(
  def: AgentDefinition,
  allocation: WorkspaceAllocation,
  deltas?: AssignmentDeltas,  // ← 新增可选参数
): MergedCapabilities {
  // Step 1: Layer 1 ∪ Layer 2（现有逻辑）
  const base: MergedCapabilities = {
    tools:  [...new Set([...def.defaultTools.map(t => t.ref),  ...allocation.tools])],
    mcps:   [...new Set([...def.defaultMcps.map(m => m.ref),   ...allocation.mcps])],
    skills: [...new Set([...def.defaultSkills.map(s => s.ref), ...allocation.skills])],
  };

  // Step 2: apply Layer 3 deltas（新增）
  if (!deltas) return base;  // 向后兼容
  return {
    tools:  subtract(union(base.tools,  deltas.addedTools),  deltas.removedTools),
    mcps:   subtract(union(base.mcps,   deltas.addedMcps),   deltas.removedMcps),
    skills: subtract(union(base.skills, deltas.addedSkills), deltas.removedSkills),
  };
}
```

冲突规则：同 ref 同时出现在 added 和 removed 时，**remove 胜出**（保守语义）。

```
┌─ 能力调整（可选）─────────────────────┐
│ 继承 def + workspace 默认能力          │
│ 额外勾选 → 加入本实例（added）         │
```

**三态 checkbox 语义**：
- ☑ = 默认状态（不在 deltas 中）

- 工具 T 在 def+ws 默认中：勾选 = 无 delta，取消 = added removed delta
- 工具 T 不在 def+ws 默认中：未勾 = 无 delta，勾选 = added added delta
- 折叠区默认收起（大多数情况不需要 override）

#### 6.4.2 `+ 上传 Skill` → UploadSkillDialog

```
┌─ 上传自定义 Skill ──────────────┐
│ 选择 .zip 文件 [选择文件...]     │
│ Skill slug（自动从 zip 推断）    │
│ SHA256: abc123...                │
│ 描述摘要（解析自 SKILL.md）       │
│                                  │
│           [取消] [上传并注册]    │
└──────────────────────────────────┘
```

**zip 结构要求**（v1.6.2 起支持三种结构）：

| 模式 | 结构 | slug 决策 |
|---|---|---|
| **A 扁平** | `SKILL.md` 在根目录 + 可选资源（`scripts/`、`LICENSE.txt` 等） | frontmatter.name 转 kebab-case → 否则 zip filename 去 `.zip` |
| **B 单子目录包裹**（向后兼容） | `<slug>/SKILL.md` + 可选 `<slug>/resources/*` | 子目录名（frontmatter.name 不覆盖） |
| **C 多子目录批量** | 多个 `<slug>/SKILL.md`（一个 zip 装多个 skill） | 各自子目录名 |

共同要求：
- **自动忽略 OS 元数据**：`__MACOSX/` 整目录、`.DS_Store`、`._*`（macOS AppleDouble）、`Thumbs.db`、`*.bak`——macOS Finder / Windows 资源管理器压缩时注入的垃圾文件不会写进 skill 目录
- **SKILL.md 路径深度** ≤ 2 段（`SKILL.md` 或 `<slug>/SKILL.md`）；深于 2 段（如 `a/b/SKILL.md`）抛错
- **SHA256 幂等**每个 skill 独立判断（批量场景下部分跳过、部分覆盖，返回数组记录全部处理结果）
- **路径防御三层**：entryName 含 `..` / rel 含 `..` / resolved path 沙箱校验，全部保留

UI 流程：
1. 用户点 `[选择文件...]` → Electron `dialog.showOpenDialog`（filters: `[{ name: 'Skill 包', extensions: ['zip'] }]`）
2. 前端读 zip 文件 Buffer → IPC 发给后端预检（不解压，仅列内容）→ 后端返回 slug + 描述（解析 frontmatter）
3. 用户确认 → 点 `[上传并注册]` → 后端解压 + SHA256 + 移动到 `<userData>/skills/<slug>/`
4. 返回成功 → 关闭弹窗 → marketplace 列表刷新

## 7. 后端改动

### 7.1 assignment-capabilities.ts（新文件）

```typescript
// electron/src/main/agent/assignment-capabilities.ts

export interface AssignmentDeltas {
  addedTools: string[];   removedTools: string[];
  addedMcps: string[];    removedMcps: string[];
  addedSkills: string[];  removedSkills: string[];
}

/** 读取某 assignment 的 deltas。无 delta 时返回全空对象。 */
export function getAssignmentDeltas(assignmentId: string): AssignmentDeltas;

/**
 * 全量替换某 assignment 的 deltas。
 * 内部：DELETE WHERE assignment_id = ? → INSERT 新值。
 * 幂等：同 deltas 多次保存结果一致。
 */
export function setAssignmentDeltas(assignmentId: string, deltas: AssignmentDeltas): void;
```

### 7.2 IPC 通道

| 通道 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `agent:getAssignmentDeltas` | `instanceId` | `AssignmentDeltas` | UI 加载时读现有 override |
| `agent:setAssignmentDeltas` | `instanceId, deltas` | void | 用户保存 override |
| `mcp:listRegistered` | — | `RegisteredMcp[]` | DefinitionEditor MCP Tab + MarketplaceView 自定义资源区 |
| `mcp:deleteRegistered` | `name` | void | 仅 source='custom' 可删；marketplace 装的报错 |
| `skill:listInstalled` | — | `InstalledSkill[]` | DefinitionEditor Skill Tab + MarketplaceView 自定义资源区 |
| `skill:uploadZip` | `Buffer, filename` | `UploadedSkill[]`（v1.6.2） | zip 上传 + SHA256 + 解压 + 注册；支持扁平/包裹/批量三种结构；返回数组（即使 1 个 skill） |
| `skill:deleteCustom` | `slug` | void | 仅 source='custom' 可删 |

#### 数据结构

```typescript
interface RegisteredMcp {
  id: string;
  name: string;
  version: string;
  command: string;
  args: string[];
  env?: Record<string, string>;
  source: 'marketplace' | 'custom';
  installedAt: string;
}

interface InstalledSkill {
  slug: string;
  name: string;          // frontmatter 解析
  description: string;   // frontmatter 解析
  source: 'builtin' | 'marketplace' | 'custom';
  installedAt: string | null;  // builtin 无时间
}
```

#### Skill zip 上传处理（skill:uploadZip）

内部步骤：
1. 接收 zip Buffer + filename
2. 计算 SHA256；同 slug 已存在 + 同 hash → 幂等返回（不重写）
3. 解压到临时目录，校验根目录有 SKILL.md
4. 解析 frontmatter（slug / name / description）
5. 移动到 `<userData>/skills/<slug>/`（已存在则覆盖，备份原目录到 `.bak`）
6. 触发 SkillRegistry 重新扫描
7. 返回 `{ slug, description }`

### 7.4 MCP 注册 source 处理

现有 marketplace installer 装包后调 `mcp:register` 时显式传 `source = 'marketplace'`（或在 installer 内部硬编码）。
新增 `+ 添加 MCP` 入口走相同 `registerMcpDefinition`，但 source = `'custom'`。

`mcp:deleteRegistered` 实现时先查 source，custom 才删；marketplace 抛错「请通过卸载按钮移除」。

## 9. 兼容性与回退

### 9.1 升级路径（v1.5 → v1.6）

- 老 DB（v15）升级到 v16：
  - 新表 `agent_assignment_capabilities` 为空（无 delta）
  - `mcp_definitions.source` 默认 `'marketplace'`、`installed_at` 默认 now
  - 所有 builtin agent 的 `default_tools` 重写为 24 工具全开 JSON
  - custom agent 的 `default_tools` 保持原样（多数是空数组 → 默认全放行 → 行为不变）
  - **零数据丢失、零行为变化**
- 老 IPC 调用站点（mergeCapabilities 不传 deltas）保持向后兼容

### 9.2 降级路径（v1.6 → v1.5）

- `agent_assignment_capabilities` 表存在但代码不读，无害
- `source` 列被忽略，无害
- builtin `default_tools` 仍是 24 工具 JSON，v1.5 代码忽略此字段（merged.tools 丢弃），无害
- **降级安全**

### 9.3 已知边界

- v1.6 前 custom agent 的 `default_tools` 多数是空数组 → merge 后仍空 → 全放行 → 行为不变。用户编辑后才会真正限制。
- builtin YAML 重新加载（每次启动）会覆盖 DB 中 builtin def 的部分字段，但**不覆盖 `default_tools`**（builtin-loader 只在首次插入时写 default*，后续以 DB 为准）—— 需在 plan 阶段验证此假设。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| builtin default_tools 修复覆盖了用户手动改过的 builtin 配置 | v1.5 用户无 UI 改 defaultTools，理论上不存在"用户改过"情况；万一有，备份原值到日志 |
| builtin-loader 行为未验证（假设它不覆盖 DB 中 default_tools，实际可能覆盖） | **plan 阶段第一步**：读 builtin-loader.ts 验证；若覆盖则 migration v16 修复策略改为「在 builtin-loader 内部硬编码 24 工具」 |
| Layer 3 delta 冲突（同 ref add+remove）| 合并算法明确：remove 胜出；UI 阻止用户同时点 add 和 remove |
| zip 上传含恶意脚本 | SHA256 校验 + 解压在临时目录 + 移动前校验 SKILL.md；不执行 zip 内任何文件；与 marketplace install 同风险级别（v2 加签名验证） |
| 自定义 MCP command 执行任意命令 | 与 v1.5 行为一致（marketplace install 也允许任意 command）；v2 加白名单 |
| allowedTools 空 = 全放行 兼容性 | mergeCapabilities 返回空数组时（罕见，仅 def+ws+deltas 都空时），permission.ts 走全放行分支；行为 = v1.5 |
