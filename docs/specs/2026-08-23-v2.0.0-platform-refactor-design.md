# Momo Studio 2.0.0 重大重构设计

> **日期**：2026-08-23
> **状态**：已与用户逐节确认（含可视化原型确认）
> **基线**：main @ v1.7.x + v2.0 平台重构（A/B/C/D 子系统）之后
> **上游输入**：`docs/2026-08-14-system-feature-inventory.md`（系统功能全景清单）

---

## 1. 背景与动机

经实际测试使用，v1.x + v2.0 混合态暴露大量问题，核心痛点集中在三处：

1. **会话体验（最大痛点）**：用户 ↔ agent、主 agent ↔ 子 agent 全部经 Matrix（Tuwunel）协议通讯。该协议在大上下文（现代模型普遍 1M token）下存在先天缺陷：
   - Matrix PDU 体积限制迫使 v1.4 实现 55KB 渐进式截断（工具字段 → thinking → 正文逐级砍）；
   - origin_server_ts 排序 + /sync 与分页各自排序，工具调用无法严格按时间线性展示；
   - 实时显示（IPC 推送）与重启历史显示（Matrix 历史聚合）双路径残余不一致，v1.7.4 连修 5 个症状 bug 仍未根治。
2. **联网需求错配**：真实需求是本地创建会话与 agent 协作完成任务，联网状态下做任务看板发布/同步、agent/MCP/skill 分享——并不需要 Matrix 的 IM 语义（房间协议、Space、bot 账号、federation）。
3. **新旧双轨复杂度**：v1 长存进程 runtime 与 v2 task-driven runtime 并存（runtime-entry.ts 1891 行按字段分流、runtime-manager.ts 905 行 deprecated 仍在服役流式转发），8/14 两轮全系统事故均源于"切换收尾漏改"。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 | 对应痛点 |
|---|---|---|
| G1 | 会话彻底脱离 Matrix：SQLite 单一真相源 + 进程内事件分发 | 大上下文截断、顺序、重启不同步 |
| G2 | UI 重构为 cherry-studio/VSCode 形态：默认全屏、titlebar workspace tabs、活动栏+侧边栏+主区 | 现有 6 视图切换形态过时 |
| G3 | 设置重构为独立界面（左菜单+右内容）：模型服务两列、默认模型四类 | provider 配置能力不足、baseUrl 启发式误判 |
| G4 | 审计日志每空间容量上限 + 滚动删除 | 无限增长 |
| G5 | 局域网联网：节点发现/信任 + 看板只读镜像 + 资源分享 | 联网协作需求（第一期） |
| G6 | 终结 v1/v2 双轨 + 清理死代码/半成品 | 复杂度与事故根源 |

### 2.2 非目标（明确排除）

- **人与人 IM 能力**：已确认 2.0 不需要真人聊天/群聊。消息模型 `sender` 字段保留 `'owner'` 语义，未来扩展留位但不设计。
- **互联网 hub 中继（momo-hub 部署）**：2.1。
- **跨节点 agent 调度 / 看板双向协同**：2.1。
- **知识库（RAG）本体**：2.1；2.0.0 仅保留向量/重排模型的设置位与数据模型。
- **主进程 ESM 转换**：拆除 matrix-js-sdk v31 锁定后可独立进行，不混入 2.0.0。
- **历史数据迁移**：已确认完全重新开始（见 §8）。

## 4. 总体架构

### 4.1 消息流（Matrix 退场后）

```
用户输入 → IPC session:send → SessionService（主进程）
  ├─ ① INSERT messages（status='done'，sender='owner'）
  ├─ ② 进程内事件分发 → RouterService → 目标 AgentRunner
  │        └─ WarmPool 取 runtime → 子进程 child IPC → LLM 循环
  │              └─ 流式 chunk → child IPC → MessageEventBuffer（50ms 批量）
  │                     ├─ INSERT message_events（seq 全序 = 时间线性显示的保证）
  │                     └─ IPC 批量推送 renderer → stream-aggregator 聚合渲染
  └─ ③ 最终态：UPDATE messages.status + final 事件（重启后同一聚合函数还原）
```

**痛点根治对应**：

| 痛点 | 解法 |
|---|---|
| 大上下文截断 | 无 PDU 限制，消息/事件全量进 SQLite，体积只受磁盘限制 |
| 工具调用线性展示 | `message_events.seq` 自增主键 = 天然全序，实时与重启同一顺序 |
| 实时/重启不同步 | 单一真相源 + 单一聚合函数（现有 A 子系统成果），传输层不再引入第二份时序 |

**复用资产**（v2.0 已验证，带测试）：RouterService、AgentRunner、WarmPool（K=2 预热）、MessageEventBuffer（50ms/30 条批落盘）、stream-aggregator（实时/重启同源聚合）、任务 8 态状态机、三层并发（全局/per-agent/provider 令牌桶）、MemoryProvider、WorkspaceFS 三重防御、24 内置工具、MCP stdio 客户端、Skill 渐进披露、资源库 ResourceItem 模型、P2P 层（Ed25519 身份 + mDNS + TCP 直连）。

### 4.2 模块处置清单

| 处置 | 内容 |
|---|---|
| **删除** | `conduit/manager.ts`（Tuwunel 进程管理）、`agent/bot-registrar.ts`、`matrix/*` 全模块（sync-manager / session / client）、Tuwunel 二进制 + 下载脚本、`matrix-js-sdk` 依赖、首启注册向导、账户设置页、v1 双轨全部（`runtime-manager.ts` 905 行、`auto-start.ts`、`task_driven` 字段分流、circuit breaker）、死代码（旧 MentionInput / InlineTaskSuggestion / CapabilityConfig / `sandbox/` 目录 / `agent:stream` 推送 / 17 个无调用方 IPC 通道，`mcp:*` 子进程内部使用除外） |
| **保留不动** | AgentRunner + WarmPool、MessageEventBuffer、stream-aggregator、任务状态机 + 调度器 + 冲突三层、P2P 层 LAN 部分、WorkspaceFS、24 工具库、MCP/Skill、资源库、MemoryProvider、keychain 抽象 |
| **改造** | RouterService（输入源：Matrix event → SessionService 进程内事件）、runtime-entry.ts 瘦身（1891 行 → 目标 <900，删 Matrix 监听分支后自然减半）、im.store → session.store、房间 IPC → session IPC（97 契约预计收敛到 ~75）、`stopAgentRuntime` 单轨化、`agent:isRunning` → lastRunning 推送（现实现保留） |

**连锁收益**：主进程 ESM 转换最大阻碍（matrix-js-sdk v31 锁定）消失；启动不再等 Tuwunel 健康检查（15s 超时风险归零）；打包不再带 Rust 二进制（macOS/Windows 预编译负担消失）。

## 5. 数据模型

### 5.1 `sessions` 表（替代 Matrix room）

```sql
sessions (
  id TEXT PRIMARY KEY,            -- randomUUID
  workspace_id TEXT NOT NULL,     -- FK workspaces（workspace 隔离，替代 Matrix Space）
  title TEXT NOT NULL,
  kind TEXT NOT NULL,             -- 'chat' | 'task_execution'
  settings_json TEXT,             -- { maxToolCalls, conflictStrategy }（吸收 room_settings 表）
  created_at INTEGER, updated_at INTEGER, last_message_at INTEGER
);
session_members (
  session_id TEXT NOT NULL,       -- FK sessions
  assignment_id TEXT NOT NULL,    -- FK agent_assignments（会话内可 @ 的 agent）
  PRIMARY KEY (session_id, assignment_id)
);
```

### 5.2 既有表语义迁移

| 表/字段 | 变化 |
|---|---|
| `messages.room_id` | → `session_id`（语义重命名，结构不动）；`sender` 改为 `'owner' | assignmentId` |
| `messages.matrix_event_id`、`source='matrix'` | 列/枚举废弃 |
| `tasks.execution_room` | → `execution_session_id` |
| `room_settings` 表 | 废弃，并入 `sessions.settings_json` |
| `agent_assignments.last_running` | 保留（在线 = 用户启动过，语义不变） |
| bot 账号概念 | 彻底消失（不再注册 Matrix bot；agent 身份 = assignmentId） |

`dispatch` / `task_reply` / `abort_dispatch` 从 Matrix 自定义 event 改为**内部消息类型**：RouterService 直接按 assignmentId 路由，不落传输层。

### 5.3 设置数据模型

| 项 | 变化 |
|---|---|
| `model_providers` | 加 `platform` 列（`'openai' | 'anthropic'`，显式指定，根治 baseUrl 启发式误判）；加预置模板标记 |
| 新表 `provider_models` | `(provider_id, model_id, enabled)`——每 provider 的模型清单，「获取模型列表」拉 `/v1/models` + 手动添加 + 启用开关 |
| `model_providers.default_model` | 废弃 |
| `global_settings` JSON | 新增四类默认模型：`defaultChatModel: {providerId, modelId}` / `defaultMultimodalModel` / `defaultEmbeddingModel` / `defaultRerankModel`（后两类 2.0.0 只存不消费） |
| 新增审计容量 | `global_settings.auditQuotaMb`（默认 100）+ per-workspace 覆盖 `workspaces.audit_quota_mb` |

### 5.4 审计日志滚动删除

- 写入路径不变（`tool_calls` 表）；新增**容量巡检**：每 N 次 INSERT（N=200）或定时（10 分钟）触发一次 `enforceAuditQuota(workspaceId)`；
- 计算 `tool_calls` 该 workspace 行数 × 平均行宽估算占用（或 `SUM(LENGTH(...))` 精确计算，写入触发时开销可接受）；
- 超限 → 按 `created_at` 升序批量 DELETE（每批 5000 行）直至回到限额内；
- 设置页显示当前占用 + 手动「立即清理」。

## 6. UI 设计

### 6.1 窗口与 Title Bar

- 无边框窗口（`frame: false`），自定义 titlebar；首次启动默认最大化，此后记住上次窗口状态；
- Title bar 布局：`[应用 Logo] [workspace tabs……] [＋] [拖拽区] [窗口控件]`；
- 每个 tab = 一个 workspace（名称 + 关闭按钮；右键菜单：重命名/删除/打开目录）；macOS 用原生红绿灯（traffic lights），Linux/Windows 右侧自绘 关闭/最小化/最大化；
- 拖拽空白区移动窗口、双击最大化。

### 6.2 导航骨架：活动栏 + 侧边栏 + 主区

```
┌─TitleBar: [◉ logo] [工作空间A][工作空间B][+] ───────────── [─ □ ✕]┐
├──┬──────────────┬──────────────────────────────────────────────┤
│活│  侧边栏       │              主区                             │
│动│ （会话列表/   │   （消息流 / Monaco / 看板 / Agent 详情…）      │
│栏│  文件树/      │                                              │
│  │  任务列表…）  │                                              │
│⚙ │              │                                              │
└──┴──────────────┴──────────────────────────────────────────────┘
```

- 活动栏（~48px 图标列）：**会话（默认）/ 文件 / 看板 / Agent / 资源库**；底部 ⚙ 设置；
- 侧边栏（~260px，`Ctrl/Cmd+B` 折叠）：内容随活动栏切换；
- 主区：现有组件大量复用——`MessageList` / `AgentStreamBubble` / `DispatchChip` / `SubAgentSection` / `TodoSection` / `CodeEditor` / task-board 全部迁入，只换外壳；
- 会话交互模型不变：多 agent 会话 + @mention（在线 = lastRunning）+ 主子 dispatch 嵌套 + 冲突弹窗 + 工具上限徽标；
- workspace 切换从左栏顶部选择器迁移到 titlebar tabs；切换时 session store / 文件树 / agent 列表按 workspaceId 重载。

### 6.3 设置（独立界面）

设置为主区级全屏页面（活动栏底部齿轮进入，Esc 返回），左菜单 + 右内容：

| 菜单 | 内容 |
|---|---|
| 模型服务 | 两列：左 provider 列表（预置模板：智谱/DeepSeek/OpenAI/Anthropic + 自定义）＋「添加」；右配置：名称 / baseURL / API Key（keychain）/ **platform 下拉** / 检查连接 / **模型列表管理**（获取模型列表 + 手动添加 + 启用开关） |
| 默认模型 | 四类各选「provider + 模型」：会话模型（agent fallback + 系统内部用途）、多模态模型、向量模型、重排模型（后两类标注"2.1 知识库启用"） |
| 会话设置 | 全局工具调用上限、任务并发数、默认冲突策略 |
| Git 策略 | 现有页面迁入 |
| 审计日志 | 现有表格 + 每空间容量上限（MB）+ 当前占用 + 立即清理 + 导出 CSV |
| 节点互联 | P2P 面板迁入（节点发现/信任列表） |
| 关于 | 版本信息 |

**删除**：账户页（Matrix 账号概念消失）、首启注册向导（首启直接进入「创建第一个 workspace」）。

## 7. 联网（2.0.0 = 局域网只读镜像）

```
本节点 SQLite 写入（messages / tasks / 资源变更）
  └→ P2pSync 广播（信任节点列表）→ 对端收到后 source='lan' 落库 + 推 UI
```

| 能力 | 2.0.0 范围 |
|---|---|
| 节点发现/信任 | mDNS 自动发现（`_momo-studio._tcp`）+ 信任列表 UI（设置→节点互联）+ Ed25519 签名验签 |
| 任务看板同步 | **只读镜像**：任务列表/状态/进度广播给信任节点；伙伴节点可查看不可操作 |
| 资源分享 | `ResourceItem.source='p2p'` 启用：信任节点的 agent/MCP/skill 在资源库「网络资源」tab 可见、可一键导入 |
| 消息互通 | P2P 广播的会话消息在对端只读展示（`source='lan'`），不可回复 |

接线工作：`initP2p` 接入 main/index.ts 启动链路（代码完整、仅缺接线）；任务表/资源库纳入 `P2pSync` 广播范围（现在只同步 message）。

## 8. 升级路径（完全重新开始）

- 版本号跳 **2.0.0**；首启检测旧版本数据目录 → 提示"全新架构，历史数据不迁移"，提供一次性全量导出（现有 Markdown 导出能力）后新建空库；

## 10. 验收标准（Definition of Done）

1. **重启一致性**：任意会话流式输出中途杀进程重启，UI 展示与重启前逐字节一致；
2. **大上下文**：单条 agent 最终消息 ≥ 1MB 正文 + 500 次工具调用事件，无截断、顺序正确、重启还原；
3. **无 Matrix 残留**：进程列表无 Tuwunel、依赖树无 matrix-js-sdk、打包体积显著减小；
4. **UI**：titlebar tabs + 活动栏 + 设置独立界面按原型落地；Ctrl/Cmd+B 折叠侧栏；
5. **设置**：模型服务两列 CRUD + 检查连接 + 模型列表；默认模型四类；审计容量滚动删除（超限自动触发）；
6. **联网**：两台局域网设备互信后，看板只读镜像 + 资源分享导入可演示；
7. **测试**：typecheck 双 clean；健康测试全绿（Matrix/双轨相关测试随代码删除）；restart-consistency 测试扩展大上下文场景。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 删除 Matrix 牵连面广（bot 注册/房间/账号/IPC 97 契约中 ~20 个） | 按「先立新（SessionService）→ 切流量 → 删旧物」三段推进，每段 typecheck + 测试门禁 |
| runtime-entry 瘦身动到大文件核心 | 只删 Matrix 分支与 v1 分流，不动 chat loop / 工具执行 / dispatch 逻辑；现有 4 场景 e2e 兜底 |
| 又现"切换收尾漏改"事故（8/14 两轮前科） | 验收标准 3（无残留）+ grep 级检查清单进 CI 讨论范围；删除项逐条打勾 |
| P2P 接线后消息回声/重复 | 广播端跳过 source≠'local' 的行（现有机制），新增 tasks/资源同步沿用同规则 + 幂等 upsert |
