# v2.1 UI 设计系统与全应用视觉重构设计（Design System & Visual Refactor）

- **日期**：2026-09-01
- **状态**：已与产品负责人逐节评审通过（视觉语言 / Token 架构与主题运行时 / 图标映射与原子组件层 / 迁移分期与强制机制四节全部确认）
- **范围**：renderer 全部 13 个功能域约 75 个生产组件；electron 主进程不涉及（无 IPC 变更）
- **上游依据**：现状基线盘点（emoji 68 处、硬编码颜色 ≈916 处、明暗模式基础设施为零）

## 1. 背景与目标

### 1.1 现状问题

1. **无明暗双主题**：`darkMode: 'class'` 是休眠配置（零 `dark:` 前缀、零 CSS 变量、零切换代码）；`globals.css` 仅 12 行且硬编码暗色——实为「伪暗色单主题」
2. **三套颜色体系并存**：自定义 token 345 处 + 标准 Tailwind 色阶 466 处（`text-neutral-*` 为主）+ inline hex 105 处，合计 ≈916 处硬编码分布在 70 个生产文件
3. **状态色漂移**：TaskChip / TaskCard / DispatchChip / ToolCallChip 四份重复调色板；`#22c55e` / `text-green-500` / `#10b981` 三套绿并存
4. **emoji 作图标**：15 处生产 UI 渲染 + 34 处测试断言 + 19 处注释，无 aria-label
5. **无原子组件层**：`ui/` 仅 Button / Input 两件，13 个域各自手写按钮/弹窗/徽标样式

### 1.2 目标

- 建立单一事实源的语义设计 token 体系（CSS 变量），支持明亮 / 暗黑双模式
- 全 app 视觉统一为「Linear 风格精密工作台」：低饱和灰阶 + 靛蓝单强调色、细边框分层、紧凑密度、小圆角
- 全部 emoji 图标替换为 lucide-react 线条图标
- 产出**可被后续 AI agent 机械遵守**的规范：文档 + ESLint + Tailwind 三层强制
- 行为不变：本次为纯视觉/样式重构，不改任何业务逻辑与 IPC 契约

### 3.7 排印

- 字体栈：`'Inter Variable', Inter, -apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif`
- 等宽栈（代码 / T-1 任务号 / 路径 / node id）：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`
- 字号阶（紧凑密度，主字号 13px）：

| 级 | 值 | 用途 |
|---|---|---|
| 页面标题 | 20px / 700 | 设置页等大标题 |
| 区块标题 | 16px / 600 | 视图标题 |
| 组件标题 | 14px / 600 | 卡片 / 分组标题 |
| **正文** | **13px / 400** | 消息、列表项、表单 |
| 辅助 | 12px / 400 | 时间戳、说明、占位 |
| 标签 | 11px / 500 / uppercase / +4% 字距 | 分组标签 |
| 等宽 | 12.5px | 代码场景 |

### 3.8 间距 / 圆角 / 阴影 / 密度

- 间距：4px 网格（4 / 8 / 12 / 16 / 20 / 24）
- 行高：会话列表 28px、设置项 32px
- 圆角：4px（chip）/ 6px（按钮、输入框）/ 8px（卡片、弹窗）/ full（头像）
- 阴影：浮层 `0 4px 16px rgba(0,0,0,.08)`（亮）/ `rgba(0,0,0,.45)`（暗）；平面容器不加阴影，用边框分层

### 3.9 图标规范

- 命名导入：`import { Star } from 'lucide-react'`（禁 CDN / 背景图 / sprite）
- 默认 `size={16} strokeWidth={1.75}`；活动栏 `size={20}`
- 颜色一律继承 `currentColor`（随文字层级自动适配明暗）
- 纯图标按钮必须有 `aria-label`
- 装载动效用 `Loader2` + CSS 旋转，不新造动画系统

### 3.10 动效与焦点

- 过渡统一 `140ms ease-out`（hover / 选中）
- **主题切换无过渡动画**（防闪烁）
- focus-visible：2px `border-focus` 外环（offset 2px），仅键盘导航显示

## 4. Token 架构

### 4.1 存储与映射（单一事实源在 CSS）

颜色变量分两种形式：

**形式一：RGB 通道三元组**（实心色，供 Tailwind 透明度修饰符使用，如 `bg-surface-2/50`）：

```css
/* renderer/src/styles/globals.css */
:root {
  --bg-canvas: 255 255 255;
  --surface-1: 249 249 250;
  --surface-2: 241 241 243;
  --text-primary: 24 25 26;
  /* …明亮全套实心色 */
}
.dark {
  --bg-canvas: 8 9 10;
  --surface-1: 16 17 19;
  /* …暗黑全套实心色 */
}
```

**形式二：完整颜色值**（alpha 随模式变化的半透明 token——surface-active、backdrop、状态色 tint。此类 token 不支持透明度修饰符，规范禁止对它们使用 `/nn` 后缀）：

```css
:root {
  --surface-active: rgba(94, 106, 210, 0.12);
  --bg-backdrop: rgba(24, 25, 26, 0.45);
  --status-success-tint: rgba(35, 131, 92, 0.12);
  --status-warning-tint: rgba(183, 121, 31, 0.12);
  --status-error-tint: rgba(211, 63, 73, 0.12);
  --status-violet-tint: rgba(110, 86, 207, 0.12);
}
.dark {
  --surface-active: rgba(94, 106, 210, 0.22);
  --bg-backdrop: rgba(0, 0, 0, 0.60);
  --status-success-tint: rgba(76, 183, 130, 0.16);
  --status-warning-tint: rgba(242, 201, 76, 0.16);
  --status-error-tint: rgba(235, 87, 87, 0.16);
  --status-violet-tint: rgba(158, 140, 245, 0.16);
}
```

```js
// renderer/tailwind.config.js —— 颜色全部映射到变量
theme: {
  extend: {
    colors: {
      canvas: 'rgb(var(--bg-canvas) / <alpha-value>)',
      surface: {
        1: 'rgb(var(--surface-1) / <alpha-value>)',
        2: 'rgb(var(--surface-2) / <alpha-value>)',
        3: 'rgb(var(--surface-3) / <alpha-value>)',
        active: 'var(--surface-active)',           // 形式二：完整值
      },
      // text / border / accent 为形式一；backdrop / *-tint 为形式二
    },
  },
}
```

语义 class 形态：`bg-canvas`、`bg-surface-1/2/3/active`、`text-primary…inverse`、`border-subtle/strong/focus`、`bg-accent-500`、`text-status-error`、`bg-status-success-tint`、`bg-backdrop` 等。`task-status.ts` 输出的徽标样式统一使用 `*-tint` 底 + 对应 `text-status-*` 前景。

### 4.2 存量硬编码映射策略

| 存量 | 去向 |
|---|---|
| `bg-bg-primary/secondary/tertiary`（345 处） | 按语境重映射 4 层 surface（旧 3 层 → 新 5 层，不能机械替换） |
| `text-neutral-100~600`（355 处） | 按文字层级映射 4 级 text token；同是 neutral-500 在标题旁是 secondary、时间戳旁是 tertiary——逐域人工裁定 |
| `bg-black` / `text-white`（40 处） | `bg-backdrop` 与 `text-inverse` |
| inline hex 状态色（105 处） | 统一进 status / task-status token；四份调色板收敛为 `task-status.ts` |
| `accent.purple` | 退役（dispatch 视觉改用 accent + task-status） |
| `bg-bg-quaternary`（未定义 token，1 处） | 修正为合法 surface 层 |

机械可映射部分用脚本批量替换，歧义处逐域人工审查。

### 4.3 Tailwind 迁移期共存与终态

- **P0**：新语义 token 与旧 token 并存（旧 token 标记 deprecated 注释），避免全 app 立即失样式
- **P4**：删除旧 token；`theme.extend.colors` 升级为 `theme.colors` **完全替换**默认色阶，仅保留 `transparent` / `currentColor` 与语义 token——裸色号类（含 `text-white` / `bg-black`，由 `text-inverse` / `bg-backdrop` 取代）从此编译即失效，这是最硬的收敛层。阴影经 `boxShadow` 主题定义，不依赖颜色色阶，不受影响

## 5. 主题运行时（纯 renderer，零 IPC）

### 5.1 theme.store（zustand）

```ts
interface ThemeState {
  mode: 'system' | 'light' | 'dark';      // 用户意图
  resolved: 'light' | 'dark';             // 实际生效
  setMode(mode: ThemeMode): void;
}
```

- 持久化：`localStorage['momo.theme']`；读取失败或非法值 → 回退 `system`
- `system` 模式下监听 `matchMedia('(prefers-color-scheme: dark)')` 变化实时更新 `resolved`（Electron renderer 的该媒体查询天然反映 OS 外观，无需 nativeTheme IPC）
- 副作用 `applyTheme()`：`resolved === 'dark'` 时给 `<html>` 加 `.dark` class，否则移除

### 5.2 防白闪

`index.html` `<head>` 内联脚本，在 React 挂载前完成 class 设置：

```html
<script>
  try {
    var m = localStorage.getItem('momo.theme');
    if (m === 'dark' || (m !== 'light' && matchMedia('(prefers-color-scheme: dark)').matches))
      document.documentElement.classList.add('dark');
  } catch (e) {}
</script>
```

### 5.3 设置入口

设置页新增「外观」分类（SettingsNav 图标 lucide `SunMoon`）：Segmented 三选一（浅色 / 深色 / 跟随系统）——Segmented 组件的第一个使用场景。

### 5.4 Monaco 适配

注册 `momo-light` / `momo-dark` 自定义主题（base `vs` / `vs-dark`），将编辑器背景、行号、选中、当前行高亮对齐 surface / accent token；`CodeEditor` 订阅 `resolved` 切换。注册异常 try/catch 回退内置 `vs` / `vs-dark`。

### 5.5 Markdown 适配

消息内代码块 / 表格 / 引用 / 链接样式集中于 globals.css 的 `.md-*` 规则，全部走语义变量。

### 5.6 字体打包

`@fontsource-variable/inter`（npm 本地打包，OFL 协议；variable woff2 ≈90KB）在 `main.tsx` 引入；CJK 走系统栈不打包。

| 组件 | 收敛的重复样式 | 要点 |

| `Avatar` | 成员 / agent 头像 | Bot 变体、名称色相派生规则 |

| `EmptyState` | 空列表 | 图标 + 标题 + 说明 + 动作按钮 |
| `Segmented` | 三态分段选择 | 主题切换器首个用户；AgentsView 双 Tab 等 |
| `Select` | 原生 select | 表单美化 |
| `Checkbox` | 能力配置大量 checkbox | 表单美化 |

**API 约定**（写入规范文档）：

1. 变体走 prop 不走 className 拼色：`<Button variant="primary">`
2. 外部 className 经 `cn()` 合并（clsx + tailwind-merge 消解冲突）
3. 原子件内部零裸色号——只用语义 token class
4. 每件贴源配套 `*.test.tsx`（renderer 单测贴源规范）
5. 存量手写弹窗迁移到 `Dialog` 是逐个替换（涉及焦点管理语义），不做批量文本替换

## 12. 风险与错误处理

| 风险 | 应对 |
|---|---|
| 迁移期新旧类共存，界面短期不一致 | 接受；按域推进，每期验收 |
| `theme.colors` 独占切换遗漏旧类 | 类编译失效即视觉缺失，靠 e2e 截图 + 逐域走查兜底 |
| Monaco 主题注册失败 | try/catch 回退内置 `vs` / `vs-dark` |
| localStorage 不可用 / 非法值 | 回退 `system` |
| Inter 加载失败 | 字体栈天然回退系统字体 |
| Tailwind 任意值 class 历史疑案（`max-w-[70%]` 失效） | 疑为动态拼接 class 致 JIT 扫描失效；规范明令禁止动态拼接 class，P0 期间顺带验证根因，若为配置问题就地修复 |
