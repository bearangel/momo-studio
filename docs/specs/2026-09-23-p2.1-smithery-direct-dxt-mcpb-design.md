# P2.1 Smithery 直连安装 + DXT/MCPB 包导入设计

- 日期：2026-09-23
- 状态：已批准（brainstorm 定稿）
- 上游：`docs/specs/2026-09-22-p2-dual-track-hub-mcp-design.md`（P2 双轨骨架）；本文为 P2 主机验收反馈（2026-09-23）驱动的迭代
- 事实底座：2026-09-23 复现取证（记入 §1）

## 1. 背景：P2 主机验收暴露的三问题与取证结论

1. **魔搭显示「网络不可达」**：Task 0 降级骨架（无公开 API）复用网络不可达文案——误导；用户裁定**放弃魔搭轨**。
2. **Smithery 无分页**：v1 只拉首页 30 条（设计缺口）。
3. **无法安装（结构性）**：实测 registry 首页 30 条 / 第 3 页 50 条 **100% hosted**（`remote:true`，stdio 零条）；`install-config` 端点 **404 已死**。P2 的「stdio 条目 → install-config → npx」前提坍塌。
4. **关键新事实（本次取证）**：`GET registry.smithery.ai/servers/{qualifiedName}` 详情返回：
   - `connections[0].deploymentUrl`（直连 MCP 端点，如 `https://brave.run.tools`，type http）
   - `connections[0].configSchema`（JSON Schema：required 字段 / properties 含 title/description）
   - 文档（smithery.ai/docs/use/connect）证实配置值经 **`x-from` 元数据**声明走 header 或 query 参数
   - → **A1 直连模式成立：免 Smithery 账号，用户自带第三方 key 直连 deploymentUrl**
5. **DXT/MCPB**：同为 zip + manifest 清单（DXT：`dxt_version` 字段，Anthropic 2025-06；MCPB：`manifest_version`，官方 modelcontextprotocol/mcpb，DXT 的标准化后继——`mcpb init/pack` 工具链）；两者 manifest 同构（mcp_servers 配置段）。

## 2. 目标 / 非目标

**目标**：
1. 魔搭轨整体移除（provider / 选择器项 / 两端枚举 `'modelscope'`）
2. Smithery hosted 条目直连安装（deploymentUrl + 用户 config → 远程 MCP 注册），复用 P2 streamableHttp 全链
3. Smithery 分页（「加载更多」）
4. DXT / MCPB 本地包导入（「＋」菜单新条目 → 解包 → S1 校验 → stdio 注册 + cwd 支持 → 卸载清理）

**非目标（P3 候补）**：OAuth 类 Smithery 服务器（gmail/github 等——需 Smithery 托管连接 API + 账号体系）；魔搭回归（若出公开 API）；skill 网络获取；MCPB 在线目录浏览（本期仅本地文件导入）。

## 3. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 魔搭全删而非隐藏 | 用户明示放弃；全仓零已装行，缩 `ResourceSource` 联合无数据风险 |
| D2 | A1 直连（免 Smithery 账号） | deploymentUrl + configSchema 实证可用；无平台依赖、隐私友好（用户 key 不过第三方）；OAuth 服务器（需托管连接）留 P3 |
| D3 | 可装判定 `installable = isDeployed && connections[0]?.deploymentUrl` | P2 的 `!remote` 在 100% hosted 现实下全灭；deploymentUrl 存在性是真实可装信号。列表接口不返回 connections——v1 以 `isDeployed` 为列表侧信号，安装时拉详情兜底校验 |
| D4 | 用户第三方 key 落 `headers_json`（明文 DB） | 与 stdio MCP 的 env key 明文落 `mcp_definitions.env` 同语义（既有先例）；终审红线（平台级 token 必须 keychain）不适用——非 Momo 主控密钥 |
| D5 | config 按 `x-from` 分 header/query，缺省 header | Smithery 文档语义；安全字段（key 类）几乎都走 header |
| D6 | DXT/MCPB 落 `source='custom'` | 与上传 skill zip 同语义（本地导入即自定义，可删可再导）；不入 installed_packages 新语义——目录清理按 `mcp-bundles/{slug}` 约定 + 记账行（item_id=`bundle:{slug}`，cache_path=解包目录） |
| D7 | `McpServerConfig`/spawn 加 `cwd?` | manifest 命令普遍是 `node server.js` 相对形态；cwd 缺省 undefined（存量零变化） |
| D8 | manifest 判别 `dxt_version` vs `manifest_version` | Cherry 同款判别（实证两种字段名）；都缺 → 拒绝 |

## 4. 设计

### 4.1 魔搭移除（契约波）
- 删 `electron/src/main/resource/hub/modelscope.ts` + 注册表项 + `isModelScopeDegraded` 消费点
- `ResourceSource` 联合删 `'modelscope'`（electron types.ts + renderer types.d.ts 镜像 + `SOURCE_LABELS`/`SOURCE_BADGE`/`resource-helpers` 三表 + `parseResourceId` 正则）
- `RegistryProviderMeta.key` 联合缩为 `'builtin' | 'smithery'`；store 白名单/记忆恢复同步（记忆了 modelscope 的存量用户回退 builtin）
- 测试：两端契约锁红测先行更新（六源标签锁缩五源）

### 4.2 Smithery 直连安装
```
RegistryBrowse 安装按钮 → store.installResource(id)
  → resource:install（smithery 分支改写）
    → GET /servers/{encodeURIComponent(slug)}（10s 超时，退避不适用——单次安装动作）
    → 校验 connections[0].deploymentUrl（https 强制）+ 读 configSchema
    → required 非空 → 返回 { needsConfig: true, schema }（renderer 弹窗）
    → renderer McpConnectDialog：按 schema properties 渲染输入框（v1 仅 string 类型）
    → 提交 → resource:installSmitheryRemote(id, configValues)
       → url = deploymentUrl +（x-from=query 的字段拼 query 参数）
       → headers =（x-from=header 或缺省的字段）
       → registerMcpDefinition(transport='streamable_http', url, headers, name=slug, source='smithery')
       → installed_packages 记账（`smithery:${slug}`，先删后插）
```
- IPC 形态：`resource:install` smithery 分支改为返回 `{ needsConfig, schema? }`；新通道 `resource:installSmitheryRemote(id, config: Record<string,string>)`（或合入 install 第二参——实现计划定，倾向独立通道语义清晰）
- 无 required（或 required 为空）→ 上述第一通道直接完成安装（免弹窗）
- `hub/smithery.ts` toEntry：`installable: raw.isDeployed`（列表侧）；错误文案：详情拉取失败/deploymentUrl 缺失 → 「该服务器暂不可直连（可能需要 Smithery 托管 OAuth）」

### 4.3 Smithery 分页
- provider `list(type, query?, page?)` → API `?q=&pageSize=30&page=`；返回 `{ entries, degraded, hasMore }`（`pagination.totalPages > page`）
- `resource:registryList` 加 `page?` 参数（缺省 1）；builtin 分支 hasMore 恒 false
- RegistryBrowse：`entries` 累加态 + 底部「加载更多」按钮（hasMore 驱动；搜索词变化/重试重置回第 1 页）

### 4.4 DXT / MCPB 导入
- 主进程新文件 `electron/src/main/mcp/bundle-import.ts`：
  - `importMcpBundle(data: Buffer, filename: string): ResourceItem`
  - zip 解包（复用 skill zip 上传所用解压库与条目数/大小限额；拒绝绝对路径/`..`/符号链接条目——同 skill zip 安全规则）
  - 根 `manifest.json` 解析 → D8 判别 → 取 `mcp_servers[0]`（v1 单 server；多 server 取首个并在返回中注明）→ S1 白名单校验（command 白名单扩 `node`/`npm` 既有集 + args 滤引号）→ slug = manifest name（过 isValidSlug，冲突后缀 `-2`）
  - 落 `<userData>/mcp-bundles/{slug}/`（先删后建，幂等重导）
  - `registerMcpDefinition({ source:'custom', command, args, env, cwd: 解包目录 })` + installed_packages 记账（item_id=`bundle:{slug}`，cache_path=目录）
- `McpServerConfig` 加 `cwd?: string`；`McpClient` spawn options 透传 cwd（undefined 时零变化）；`mcp_definitions` migration 039 加 `cwd TEXT` 列（nullable，stdio bundle 行使用）
- 卸载：`resource:delete` custom+mcp 分支扩展——name 命中 `bundle:` 记账行 → 删行 + rm 解包目录
- UI：MCP 页「＋」下拉加「导入 DXT / MCPB 包」（`AddMenu` 数组 + 新 `ImportBundleDialog`：文件选择（`.dxt/.mcpb/.zip`）→ manifest 预览（server 名/命令/版本）→ 确认导入；复用 UploadSkillDialog 的文件交互模式）

## 5. 错误处理
- 详情拉取失败（网络/404）→ 可操作中文错误（含重试提示）；deploymentUrl 非 https → 拒绝
- config 提交后连接失败不在安装时验证（安装=注册；连接失败由运行时池语义暴露——与 stdio npx 安装同语义）
- bundle：非 zip/manifest 缺失/双判别字段缺失/S1 拒绝/解压超限 → 中文错误拒绝且不留半解包目录（temp 解包后原子 rename）
- 分页空页/越界 → 空 entries + hasMore=false

## 6. 安全
- D4 密钥语义（用户 key 落 headers_json 同 env 先例）；deploymentUrl 强制 https；config 值不落日志
- bundle zip 路径逃逸防线（同 skill zip 规则）；manifest command 走 S1 白名单——bundle 内文件本身是任意代码（与用户手动 npx 同信任级，UI 预览明示「将运行包内程序」）
