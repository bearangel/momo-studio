# P2.2 已装远程 MCP 配置编辑 + MCP 引用对齐 — 设计

- 日期：2026-09-23
- 状态：已批准（用户 2026-09-23 四问裁定：范围 B / schema 来源 A / 仅远程 / 提示卡 A）
- 上游：P2.1（Smithery 直连 + DXT/MCPB，`2026-09-23-p2.1-smithery-direct-dxt-mcpb-design.md`）
- 版本：合入后 `2.1.0-alpha.4`

## 1. 背景与问题

P2.1 上线后主机实测暴露两个「装完就断联」问题：

**问题 A（无配置编辑入口）**：Smithery 安装时 API key 等配置经 McpConnectDialog
收集，烘进 `mcp_definitions.headers_json`（x-from=query 字段拼进 url）后**全应用
没有任何查看/修改入口**。key 填错、或可选 key 空着装（如 context7，空 key 直接
HTTP 401）时，用户唯一出路是卸载重装。日志实证：`upstash/context7-mcp` 远程
initialize 401，无自救路径。

**问题 B（引用名字对不上 → 悬空）**：agent 定义经 `defaultMcps`
（`[{kind:'mcp', ref: <名字>}]`，存 `agent_definitions.default_mcps` JSON 列）
**按名字精确引用** MCP；运行时逐名查 `mcp_definitions`，查无即「MCP xxx 未注册」
（静默跳过该 server）。用户 agent 引用 `filesystem`，Smithery 装的注册名是完整
slug——名字对不上，每回合报未注册。且卸载 MCP 不清理 agent 侧引用，会持续制造
新悬空。

## 2. 目标与非目标

**目标**：
1. 已装远程（streamable_http）MCP 可查看/编辑配置（url + API key 等字段），保存后
   即时生效（驱逐池连接，下回合重建）
2. 卸载任意 MCP 时自动从 agent 定义移除引用（不再产生新悬空）
3. MCP 资源页展示「未满足引用」提示卡，点名悬空引用（覆盖名字对不上场景）

**非目标（P3 延期）**：stdio MCP 编辑（command/args/env/cwd）；agent 编辑器内 MCP
引用下拉选择器；「测试连接」按钮；Smithery OAuth 托管连接。

## 3. 数据层（migration 040）

`mcp_definitions` 加列：

```sql
ALTER TABLE mcp_definitions ADD COLUMN config_schema TEXT NOT NULL DEFAULT '{}';
```

- 存 JsonSchemaLike 序列化（Smithery 详情 configSchema 消费面形状）
- 安装链 `installSmitheryRemote` 落库时写入（含 schema 缺省 undefined → `'{}'`）
- 存量行（用户已装的 context7）为 `'{}'` → 编辑时走 §5.1 降级链
- migration 040 含 down（DROP COLUMN——SQLite 3.35+ 支持，与既有 038/039 同法）

## 4. IPC 契约（resource 命名空间，renderer `types.d.ts` 镜像 + preload 三层）

### 4.1 `resource:getMcpConfig(name)` → `McpConfigView`

```ts
interface McpConfigView {
  name: string;
  transport: 'stdio' | 'streamable_http';
  /** 裸模式标志：无 schema 时 true，前端渲染 url 整条 + headers 键值行 */
  bare: boolean;
  /** schema 模式的字段元数据（bare=false 时必有；裸模式键缺省而非 undefined 值） */
  schema?: JsonSchemaLike;
  /** 各字段现值回显（schema 模式：header 字段取 headers_json，query 字段从
   *  url query 参数按字段名 decodeURIComponent 反解；裸模式为空对象） */
  values: Record<string, string>;
  /** 远程端点整条（裸模式可编辑回显用） */
  url: string;
  /** 裸模式的现有 headers 键值（schema 模式为空对象） */
  headers: Record<string, string>;
}
```

### 4.2 `resource:updateMcpConfig(name, input)` → `void`

```ts
interface McpConfigUpdateInput {
  url: string;                        // 须 https（与安装链同防线）
  config: Record<string, string>;     // schema 模式：字段级值
  headers?: Record<string, string>;   // 仅裸模式：整包 headers 覆盖
  schema?: JsonSchemaLike;            // 编辑期间拉到的新 schema 顺手落库
}
```

### 4.3 `resource:danglingMcpRefs()` → `DanglingMcpRef[]`

```ts
interface DanglingMcpRef {
  refName: string;                    // 悬空引用名（如 'filesystem'）
  agents: Array<{ definitionId: string; name: string }>;
}
```

## 5. 主进程逻辑

### 5.1 getMcpConfig 三级 schema 降级

1. `mcp_definitions.config_schema` 非 `'{}'` → 直接用
2. 为空且 `source='smithery'` → `fetchSmitheryDetail(slug)` 实时拉
   `connections[0].configSchema`；**拉到顺手 UPDATE 回写**（下次离线可用；回写失败
   仅 warn 不阻塞）
3. 拉取失败/非 smithery 远程 → `bare: true` 裸模式

### 5.2 updateMcpConfig

- 校验：目标存在、`transport='streamable_http'`、url 以 `https://` 开头、config 值
  trim 后空串剔除（同安装语义：可选字段空值不下发）
- schema 模式：复用安装链 x-from 分流逻辑——**从 `installSmitheryRemote` 抽出共享
  函数 `composeRemoteConfig(url, config, schema)`**（返回 `{ finalUrl, headers }`），
  安装/编辑两处单点维护
- 裸模式：直接用 input.url + input.headers
- `UPDATE mcp_definitions SET url=?, headers_json=?, config_schema=? WHERE name=?`
  （**不换 id、不重置 installed_at**——不复用 registerMcpDefinition 的 REPLACE）
- **name 级池驱逐**：host-manager 新增 `evictMcpByName(name)`——遍历池 key
  `endsWith(':' + name)`（workspaceId 为 uuid 不含 `:`，slug 不含 `:`，无歧义），
  逐个照 `stopMcp` 语义删除并 disconnect（try/catch 启动失败态）

### 5.3 卸载级联清理

`deleteRegistered(name)`（全来源删除断面，marketplace 保护语义不变）**不在其函数
体内做级联**——mcp 层反向 import agent/crud 会造成循环依赖（agent 层已 import
host-manager 经 runtime-spawner）。三个 deleteRegistered 生产断面
（`bundle-import.ts:569` / `resource/ipc.handlers.ts:239` / `hub-install.ts:146`
deleteRegisteredHubSafe→uninstallHubMcp）各自在**删行成功后**调
`removeMcpRefsFromAgents(name)`（定义于 `agent/crud.ts`）：扫
`listAgentDefinitions()`，凡 `defaultMcps` 含匹配 ref 的行，
`updateAgentDefinition` 覆盖为剔除后的数组（其余 ref 保留）。日志记录被清理的
agent 名单。bundle 导入/手动注册的卸载经同一断面自动覆盖。

### 5.4 dangling 扫描

`listAgentDefinitions()` 全量（含已启用 builtin 的 DB 行）的 `defaultMcps[].ref`
与 `listRegistered()` 名字集比对，查无者按 refName 聚合出 agent 名单。扫描异常
logger.warn + 返回空数组（卡片静默不显示）。

## 6. UI（renderer）

### 6.1 ResourceDetail「配置」按钮

显示条件：已装 MCP 条目且 `custom.transport === 'streamable_http'`。所有从
`mcp_definitions` 产出 ResourceItem 的填充函数（hub 已装列表 / 手动注册 /
bundle 条目）统一在 `custom` 载荷带上只读 `transport` 字段，与卸载按钮并排显示。

### 6.2 McpConfigDialog（新组件）

- 复用 McpConnectDialog 骨架与锁定交互（提交期禁闭全部可交互元素、Esc/遮罩
  no-op、失败红字留弹窗可重试、成功自关）
- schema 模式：按 `schema.properties` 渲染字段（label=title，placeholder=
  description 截断 64），`values` 回显现值（API key 明文回显——本地单用户应用，
  headers 本就明文存 DB；不引入 password 语义）
- 裸模式：url 整条 Input + headers 动态键值行（可增删行）
- 提交走 View 层接线 `ipc.resource.updateMcpConfig`；裸模式提交
  `headers` + `url`，schema 模式提交 `config`（+编辑期间拉到的 schema 透传落库）

### 6.3 DanglingRefsCard（新组件）

MCP 标签页顶部（TypePageShell）条件渲染：`danglingMcpRefs()` 非空时显示
「N 个 agent 引用了未安装的 MCP：filesystem（coder）…」+ 一句指引（去 Smithery
搜索安装，注册名需与引用名一致；或编辑 agent 引用）。空数组/加载失败不渲染。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 编辑时 Smithery 拉取失败 | 中文错误提示一次 + 自动落裸模式，不阻塞编辑 |
| 回写 config_schema 失败 | logger.warn，编辑流不受影响 |
| update 目标不存在 / 非 streamable_http | 明确中文错误，弹窗红字 |
| url 非 https | 前端禁提交 + 主进程双防线拒绝 |
| dangling 扫描异常 | warn + 空数组，卡片不显示 |
| 卸载级联中单行 update 失败 | warn + 继续清其余行（不被吞掉）；名单只含成功者；失败行的悬空引用由 §5.4 扫描 + §6.3 DanglingRefsCard 兜底可见（D8 决策——级联后置断面后，若整体上抛反而破坏卸载原子性，参考 §5.3 理由） |

## 9. 决策记录

- D1 编辑只做远程条目（stdio 四件套编辑 P3）
- D2 schema 三级降级（库存 → 实时拉回写 → 裸表单）——新装离线可编辑，存量可救
- D3 API key 明文回显（本地单用户，不引入敏感语义）
- D4 UPDATE 专用语句而非 registerMcpDefinition REPLACE——保 id/installed_at
- D5 级联清集中在 deleteRegistered 断面（全来源统一，含 bundle/手动）
- D6 dangling 扫描面 = DB 全量 agent 定义（未启用的 catalog-only builtin 不扫——
  现行 builtin YAML 无 mcps 引用，无实际损失）
- D7 提示卡只提示不自动修复（agent 编辑器改造 P3）
- D8 卸载级联单行 update 失败不整体上抛——warn + 继续清其余行 + 名单只含成功
  者；失败行的悬空引用由 §5.4 dangling 扫描 + §6.3 DanglingRefsCard 兜底可见
  （级联后置断面后，整体上抛会破坏卸载原子性：mcp 行已删 + 记账行残留成孤儿）
- D9 **renderer schema 模式编辑时 input.url 须为去 query 的 base url**——表单
  预填取 `view.url.split('?')[0]`；否则 `composeRemoteConfig` 会追加第二个同名
  参数，连接发双份 query
