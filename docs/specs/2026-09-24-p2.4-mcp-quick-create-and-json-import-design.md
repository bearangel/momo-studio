# P2.4 MCP 快速创建 + JSON 导入增强 设计

- 日期：2026-09-24
- 状态：已批准（用户逐节确认）
- 范围：renderer 资源库 MCP 页新增/导入体验；electron 仅 IPC 契约透传
- 上游：P2.2（已装远程 MCP 配置编辑）、P2.1（DXT/MCPB 导入）、P2 传输二态转正

## 1. 背景与问题

用户报四项体验缺口（2026-09-24）：

1. 「手动配置」表单（`RegisterMcpDialog`）**无传输类型**——永远注册 stdio；IPC `registerMcp` 已支持 `transport:'streamable_http'+url`（P2 Task 7 二态透传）但表单未暴露
2. 表单**环境变量行只能加不能删**（`[+] 添加环境变量` 只追加，行内无删除钮）
3. 远程条目**没地方填 headers**（如 context7 的 `Authorization`）；且 IPC 契约 `RegisterMcpInput` 本身缺 `headers` 字段（DB 落库端 `registerMcpDefinition` 支持，IPC 不透传）
4. 「粘贴 JSON」示例是一行 JSON 串不友好；各家 AI agent 的 JSON 格式未全兼容

现状盘点（探索结论）：

- 表单其余缺口：args 逗号分隔（`--port 3000` 靠空格拆开是歪打正着，带空格参数值必坏）；同名静默覆盖（INSERT OR REPLACE，无确认）；cwd 列被 stdio spawn 消费但表单未暴露
- JSON 解析（`mcp-json.ts`）现状支持：`mcpServers` 包裹 + 裸对象；stdio（command/args/env）+ 远程（url 有无推断二态，强制 https）。不支持：`headers`、`type:"sse"`（会被**静默误注册**成 streamable_http，连接时才失败）、VS Code `servers` 键、type 与字段矛盾检测
- 传输支持面：stdio（`McpClient` 子进程）+ streamable HTTP（`HttpMcpClient`）；**SSE 旧传输无客户端实现**（本轮明确不做，见 D1）

## 2. 目标 / 非目标

**目标**

- 快速创建表单完整覆盖 MCP 新增需求：传输二态、headers、env 行删除、args 修复、cwd、同名覆盖确认
- 导入 JSON 兼容三家格式（Claude Desktop/Cursor 的 `mcpServers` + VS Code 的 `servers` + 裸对象），远程条目带 headers，SSE 明确报错
- 结构化多行示例一键插入
- 入口改名：「手动配置…」→「快速创建…」；「粘贴 JSON…」→「导入 JSON…」

**非目标**

- SSE 传输客户端实现（D1）
- stdio MCP 的**编辑**（注册后改配置——现状只有远程条目有 McpConfigDialog 编辑；stdio 编辑仍走「卸载重装」）
- Smithery `run.tools` 平台代理包装格式（平台 token 语义，不适合直导；P3 OAuth 备案）
- 已装 MCP 列表页/详情页改动（零涉及）

## 4. 快速创建表单设计

`RegisterMcpDialog.tsx` 原地升级（文件名与组件名不变，避免测试/挂载点大迁移）；AddMenu 文案「快速创建…」hint「本地 stdio / 远程 HTTP 二态」；弹窗标题「注册自定义 MCP server」→「快速创建 MCP」。

### 4.1 传输二态（顶部 Segmented，复用 `components/ui/Segmented`）

| 态 | 必填 | 可选（高级折叠区） | 隐藏字段 |
|---|---|---|---|
| 本地（stdio，缺省） | 名称 / 命令 | 参数（textarea 一行一个）；环境变量（KeyValueRows）；工作目录 cwd（Input） | url / headers |
| 远程（streamable HTTP） | 名称 / URL（须 https） | 请求头（KeyValueRows） | command / args / env / cwd |

- 切换传输态清空对方态专属字段（防脏数据残留误提交）
- 远程态 URL 前端先挡非 https（提交按钮 disabled + 提示），主进程 https 校验双防线不变
- 版本字段两态共用保留（可选）

### 4.2 KeyValueRows 子组件（新文件）

Props：`{ rows: Array<{key:string; value:string}>; onChange: (rows) => void; keyPlaceholder; valuePlaceholder; addLabel }`。

- 每行：KEY Input + VALUE Input + 行尾删除钮（lucide `X` 14px stroke 1.75，语义 token 着色，aria-label「删除该行」）
- 底部「+ 添加」文字钮追加空行
- 提交侧过滤：key/value 任一为空的行静默剔除（组装 env/headers 对象）
- env 与 headers 实例化两次复用同一组件

### 4.3 同名覆盖确认（二段式）

1. 点「注册并启动」→ 先 `ipc.resource.list({type:'mcp'})` 查 slug 集合（与 JSON 导入预检同手法）
2. 同名 → 表单内警示条（`text-status-warning`）「将覆盖同名服务器：xxx」+ 主按钮文案变「确认覆盖」
3. 再点才真正提交；期间改任一字段重置回一段态（警示条消失）

### 4.4 提交流程（不变部分）

注册（`resource:registerMcp`）→ 当前 workspace 启动（`mcp:start`）→ onSuccess 刷新 → onClose。提交期间按钮 disabled；失败红字留弹窗。

## 5. IPC 契约扩展（两端镜像）

`RegisterMcpInput`（renderer `types.d.ts` 与 electron `ipc.handlers.ts` 双端）增两可选字段：

```ts
/** 远程条目请求头（transport='streamable_http' 生效；含鉴权 key，沿用不落日志纪律） */
headers?: Record<string, string>;
/** stdio 条目子进程工作目录；缺省不传（与 bundle 导入 spawn 同语义） */
cwd?: string;
```

- electron handler 透传 `registerMcpDefinition`——落库端已支持（headers_json / cwd 列），**零改动**
- preload 已按整体对象透传 `registerMcp`，无新通道

## 6. 导入 JSON 设计

### 6.1 解析扩展（`renderer/src/lib/mcp-json.ts`）

- **顶层三态识别**：`raw.mcpServers` → `raw.servers`（VS Code）→ 裸对象。识别优先级固定，`servers` 键存在但形态非法时错误信息提示「VS Code 格式（servers 键）」
- **type 权威判定**（单条目）：
- `type === 'sse'` → 抛错 `服务器 "xxx"：暂不支持 SSE 传输（仅支持 stdio 本地与 streamable HTTP 远程）`
- `type` 为 `'http'` / `'streamable-http'` / `'streamable_http'`（三种拼写归一）→ 按远程：url 必填且 https，可带 headers；出现 command → 抛矛盾错
  - `type === 'stdio'` → 按本地：command 必填；出现 url → 抛矛盾错
  - 无 type → 现状推断（url 非空即远程）
- **headers 解析**（远程条目）：`Record<string,string>` 校验（键值非字符串抛错，与 env 同模式），透传 `ParsedMcpEntry.headers`
- `ParsedMcpEntry` 增 `headers?: Record<string, string>`
- `McpJsonPasteDialog.handleImport` 注册调用透传 `headers`

### 6.2 示例与文案

- 「插入示例」文字钮（输入区旁）：textarea **空**时点击直接填入；**非空**时按钮变「确认替换」二段式（与同名覆盖确认同模式，点击后填入）：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_xxx" }
    },
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp",
      "headers": { "Authorization": "Bearer <你的 API Key>" }
    }
  }
}
```

- placeholder 精简为一句：「支持 mcpServers / servers（VS Code）/ 裸对象；远程须 https」
- 弹窗标题「粘贴 JSON 导入 MCP」→「导入 JSON」；label「粘贴 JSON」→「导入 JSON」；AddMenu 项「粘贴 JSON…」→「导入 JSON…」
- 预览列表徽标维持 远程/本地（VS Code 条目同规则）

## 7. 错误处理汇总

| 场景 | 行为 |
|---|---|
| 远程态 URL 非 https | 提交按钮 disabled + 字段下提示 |
| 表单提交失败 | 红字留弹窗（现状） |
| 同名 | 二段式确认（§4.3） |
| JSON 根非法/空对象 | 中文报错（现状延续） |
| `type:"sse"` | 明确报「暂不支持 SSE 传输」（不再静默误注册） |
| type 与字段矛盾 | 报错指出具体矛盾（`type:"stdio" 但只有 url` 等） |
| headers/env 非字符串值 | 报错含条目名与字段名（现状 env 同模式） |
| 导入逐条失败 | 逐条收集到 done 阶段展示（现状） |

## 9. 风险与开放问题

- `RegisterMcpDialog` 组件名与文件名保留（D7），但语义已从「注册自定义」变「快速创建」——注释与文档同步更新，不迁移文件（降低 diff 噪音）
- VS Code `servers` 格式的远程条目在 VS Code 侧写法是 `"type": "http"`（2025-04 起统一 http/sse/stdio 三态），与本设计 type 权威判定一致，无额外分支
- 示例中 `<你的 API Key>` 占位符：导入后 headers 原样落库，用户须用 P2.2「配置」按钮改真 key——示例文案中明示「导入后记得在配置里替换占位符」
