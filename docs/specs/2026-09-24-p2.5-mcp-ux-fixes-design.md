## 1. 问题清单（复现定位）

| # | 现象 | 根因 |
|---|---|---|
| ① | 快速创建 stdio 参数输入高度不够 | `RegisterMcpDialog` 参数 textarea `rows={3}` |
| ② | 导入 JSON 输入框高宽不足 | `McpJsonPasteDialog` Dialog `width={520}` + textarea `rows={8}` |
| ③ | 导入完成需手动关弹窗 | done 阶段在弹窗内展示结果摘要 + 关闭按钮 |
| ④ | stdio MCP 无编辑入口；远程仅能改连接参数 | `ResourceDetail`「配置」按钮门控 `custom?.transport === 'streamable_http'`（P2.2 D1：stdio 不编辑）；`McpConfigDialog` 仅 url/headers |
| ⑤ | 删除资源无确认直接执行 | `ResourceRow`/`ResourceDetail` 的 `onDelete` 直连 `store.deleteResource`，三类型均无确认 |

## 2. 决策记录

| # | 决策 |
|---|---|
| D1 | 参数 textarea `rows` 3→6（保留 `resize-y`） |
| D2 | 导入弹窗宽 520→640、textarea `rows` 8→14 |
| D3 | 导入完成交互：**全部成功 → 自动关弹窗 + installNotice 绿色横幅**「导入成功 N 条 MCP」（复用 TypePageShell 既有横幅机制，弹窗内直接 setState store——与 View 层 `handleMcpConfigSubmit` 同模式）；**存在失败 → 留弹窗**展示失败明细（既有 done 阶段），不打扰性关闭 |
| D4 | **MCP 全字段编辑**：已装 `source='custom'` 的 MCP（stdio + 远程，含快速创建/JSON 导入产物）详情页加「编辑」按钮 → 快速创建表单复用为编辑模式（预填全字段，名称只读——name 是 agent 引用键，改名=破坏引用，不做）；提交走新通道保 `id`/`installed_at`/`source` 的 UPDATE + 池驱逐 + 当前 workspace 重启；smithery/marketplace 源的「配置」按钮保留（连接参数/schema 专用，P2.2 链路不动）。编辑模式允许切换传输类型（stdio↔远程，表单既有切换清空逻辑复用） |
| D5 | **删除确认**：新 `ConfirmDialog` 原子件；`TypePageShell` 层拦截 `ResourceRow`/`ResourceDetail` 的 onDelete → 确认弹窗（标题「删除 {name}？」，正文「此操作不可撤销」，MCP 附加「引用它的 agent 将出现悬空提示」）→ 红色危险钮确认后才执行 `deleteResource`。三类型（mcp/skill/agent）统一 |

## 3. MCP 编辑链路设计（D4 详设）

### 3.1 electron 服务（`resource/mcp-config.ts` 追加）

```ts
/** 全字段编辑视图（stdio + 远程通吃；renderer types.d.ts 镜像） */
export interface McpEditView {
  name: string;
  transport: 'stdio' | 'streamable_http';
  version: string;
  command: string;
  args: string[];
  env: Record<string, string>;
  url?: string;             // 仅远程
  headers: Record<string, string>;  // 仅远程（stdio 空对象）
  cwd?: string;             // 仅 stdio
}

export function getMcpEditView(name: string): McpEditView;   // 未注册抛中文错
export async function updateMcpEntry(name: string, input: McpEntryUpdateInput): Promise<void>;
// 校验（存在/https）→ UPDATE transport/version/command/args/env/url/headers_json/cwd（保 id/source/installed_at/config_schema）→ evictMcpByName → broadcastLocalResourceCatalog（fire-and-forget）
```

`McpEntryUpdateInput` 与 `RegisterMcpInput` 同形（transport/version/command/args/env/url/headers/cwd 全可选除 command）。

### 3.2 UPDATE 语义（`host-manager.ts` 追加 `updateMcpEntryDefinition`）

- 与 `registerMcpDefinition` 同构的字段组装（远程 command 空串占位/stdio url·headers 落 NULL/https 校验），但走 `UPDATE … WHERE name = ?` 不触碰 id/source/installed_at/config_schema
- `updateMcpEntry`（mcp-config.ts）负责驱逐池连接——编辑后旧进程/旧连接立即失效，下次 `getOrStartMcp` 按新定义重建

### 3.3 IPC 双端

- `resource:getMcpEditView (name) => McpEditView`
- `resource:updateMcpEntry (name, input) => void`
- preload + `types.d.ts` ApiSurface 镜像

### 3.4 renderer 编辑模式（`RegisterMcpDialog` 复用）

- Props 追加 `edit?: { name: string }`——传入即编辑模式：标题「编辑 MCP」、名称 Input disabled、mount 拉全字段预填（args 按 `\n` join、env/headers Record→行数组）、无同名二段确认（名称不可改）
- 提交流程：`updateMcpEntry(name, payload)` → `mcp.start(activeWorkspaceId, name)`（重建连接，同创建流）→ onSuccess + onClose；失败红字留弹窗
- `ResourceDetail`：`item.type === 'mcp' && item.installed && item.source === 'custom'` 显示「编辑」按钮（新 Props `onEditMcpEntry`）；既有「配置」（streamable_http 门控）保留
- `ResourceLibraryView`：`editTarget` state 挂载 `<RegisterMcpDialog edit={{ name }} …>`

## 4. 删除确认设计（D5 详设）

- 新 `renderer/src/components/ui/ConfirmDialog.tsx`：`{ title, message, confirmLabel?, onConfirm, onClose }`——Dialog 骨架 + message 段落 + 取消/危险确认双钮（Button `variant="danger"`）
- `TypePageShell`：`pendingDelete: ResourceItem | null` state；行/详情 onDelete 改为 `setPendingDelete(item)`；确认 → `deleteResource(item.id)` + 清 state；MCP 类型 message 追加悬空提示句

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| 编辑视图读不到（未注册） | 中文红字（弹窗内） |
| 编辑提交 url 非 https | 前端 disabled + 主进程双防线（与创建同口径） |
| 编辑提交失败（含 mcp.start 失败） | 红字留弹窗（定义已更新，重启失败如实展示） |
| 确认弹窗 Esc/遮罩/取消 | 关闭不删除 |
