# M5.3 设计：外派团队执行 + 镜像模型自动配平

- 日期：2026-10-30
- 状态：已与用户逐项裁定（三问三裁），待 Momus 审
- 交付物：hub v0.5.0（协议 1.9.0）+ studio alpha.49
- 上游：`docs/specs/2026-08-31-agent-team-session-redesign.md`（团队/双会话域）、M2.x 委派链、M4.3 派发闸

## 1. 背景与问题

用户真机验收发现两断点：

1. **外派任务只有单 agent 形态**：`CreateTaskDialog` 外派分支（routing=组内调度/指定节点）隐藏委派目标区，payload 只带 `agentSlug`（空=目标空间默认 agent）；接收端 `delegation-runner.handleAssigned` 解析出单个 agent → `createDelegatedSession` 单成员会话直接开跑。复杂任务需要团队（leader + 成员、leader 可 dispatch 子 agent）协作，外派路径无通路。
2. **镜像 agent 无 LLM 配置**：每 agent 模型绑定存 `agent_definitions.model_provider_id + model_name`（providerId 是本机 DB 行 id，跨节点无意义）；快照只带全局默认模型（modelBinding 段，D4/T16b），不带每 agent 绑定。镜像后 agent 在目标节点是「能看不能跑」的空壳（`buildSpawnOpts` 对未配置 def 直接 throw），用户必须切到目标节点逐一配置。

## 2. 目标 / 非目标

**目标**

- F1 外派团队执行：派发时可选「团队协作」——成员名单随任务走，接收端建多成员执行会话（leader 接待 + dispatch 注入），机制与本地团队任务同构
- F2 镜像模型自动配平：每 agent 模型绑定按名对齐到目标节点，**只补空**，四级链
- F3 防呆：成员缺失 decline + 人话名单；提交预检提示

**非目标（票桶）**

- 在途调组：派发时刻成员快照定型，运行中不增删（与本地团队会话快照语义一致）
- 临时多选组队：V1 派发侧只选团队下拉（快照选择器），不支持手拼成员名单
- agent 自判复杂度升级为团队（escalation）
- F2 不自动给 provider 增补模型条目（只查 `provider_models` 已配置面，不写 provider 表）
- 团队任务的差异化进度聚合面板（子 agent 流沿用现有 dispatch chip 呈现）

## 4. 实证依据（2026-10-30 代码实查）

- **hub 任务书白名单校验**：`momo-hub packages/hub/src/delegations.ts parseDelegationTask` 按已知字段重建 task 对象——未知字段静默剥除。`team` 段必须改 hub（校验 + `DelegationTask` 类型 + 协议号），hub 先行发版。
- **快照成员/团队形态**：`snapshot-builder` 收集 `SnapshotAgentMember`（name/slug/customDefinition 三态）与 `SnapshotTeam`（name/leader/members 全按 agent 名对齐）；applier 按名重建成员与团队。custom YAML 刻意不带模型绑定（providerId 跨节点无意义）。
- **D4 自愈① 先例**：`mirror-applier` 重镜像复用既有定义时，若目标 def 已有 `modelProviderId` 则保留（防 INSERT OR REPLACE 清回 NULL）——F2「只补空」是该逻辑的完整化（从「保留」扩展为「保留 + 对空者四级配平」）。
- **dispatch 注入零新增**：`buildDispatchSnapshot`（spawn-helpers）按 session_members 判定「成员 >1 且 is_leader」注入 `dispatch:<slug>`；多成员执行会话建好后 leader 的 dispatch 能力自然成立，无需新机制。
- **委派接收端现状**：`handleAssigned` 单 agent 解析（agentSlug ?? 默认 agent）→ `createDelegatedSession`（单成员）；decline 机制已有（acceptTasks/并发上限/空间不存在/agent 缺失四闸）。

## 5. F1 外派团队执行

### 5.1 hub 协议（v0.5.0，协议 1.8.0 → 1.9.0）

任务书 `DelegationTask` 新增可选段：

```ts
team?: {
  members: Array<{ name: string; isLeader: boolean }>;
};
```

校验规则（`parseDelegationTask` 扩展，**非法整包拒**——沿 dependsOn 先例：team 是派发核心语义，静默剥除会让接收端误解为单 agent）：

- `members` 数组，2..8 项；每项 `{ name: 1..64 字符, isLeader: boolean }`
- 恰好 1 项 `isLeader=true`（0 个或 ≥2 个 → 拒）
- `team` 与 `agentSlug` **互斥**（同时在场 → 拒，bad_request）
- `team` 随 `task.assigned` 事件透传，hub 不持久化（与 agentSlug/dependsOn 同生命周期——账本只存 taskId/title/prompt）

**hub 侧版本门（防旧 studio 静默降级）**：旧版 studio 对未知 `team` 字段会忽略并按单 agent 跑——正是裁定 3 禁止的静默换班。hub 在 `handleDelegate` 时按节点 protoVer 门禁：

- 指定节点：目标 protoVer < 1.9.0 → 拒（`目标节点 <名> 协议过旧，不支持团队派发`）
- 组内调度：**least-busy 候选池排除** protoVer < 1.9.0 的节点；池空 → 拒（人话列全部落后节点）

hub 侧配套：`AssignedTaskEvent`/`DelegationTask` 类型、错误文案、`routingPrecheck` 返回值增节点能力面（见 5.4）。测试并入 hub 332 基线。

### 5.2 派发方（studio）

- `CreateTaskDialog` 外派分支（`remoteRouting`）新增「执行方式」Segmented：**单 agent**（默认，现状零变化）/ **团队协作**
- 团队协作 = 本 ws 团队下拉（展示 leader 名），提交时**展开为成员名单快照**（`listTeams` 当前成员 + leader 标记，与本地团队任务建会取快照同语义）
- `submitRoutedTask` payload：单 agent 带 `agentSlug`（不变）；团队带 `team.members`（name=agent 定义名，与快照名对齐口径一致）
- 批量模式不提供团队选项（批量行无法逐行指团队；票桶）

### 5.3 接收端（studio）

`delegation-runner.handleAssigned` 新分支（`evt.task.team` 在场）：

1. `findWorkspaceByName` → 逐名解析成员（镜像/本地成员表按 agentName 匹配）
2. **任一失败 → decline**，原因：`团队成员无法解析: <缺失名单>（工作空间 <名> 无这些 agent）——请先镜像工作空间或改派`
3. 全部解析 → `createDelegatedSession` 扩展：`members: Array<{instanceId, isLeader}>` → 多成员会话（kind='task_execution'，成员全入 session_members，leader `is_leader=1`）
4. kickoff mention leader → 接待路由给 leader
5. 权限档位 / readonly 标记 / 进度上报 / 取消 / HITL 全沿用现状（挂 session，与成员数无关）
6. leader spawn → `buildDispatchSnapshot` 自然注入 `dispatch:<slug>`（会话内成员快照过滤）

单 agent 路径（agentSlug / 缺省默认）零变化；无 `team` 段的旧 payload 行为不变。

### 5.4 版本门与预检（F3）

- **协议门**：hub 1.9.0 起认 team 段。双层防线：
  - **studio 派发闸**（提交时早失败）：指定节点目标 protoVer ≥ 1.9.0，否则拒提交（人话：`目标节点 <名> 版本过旧（协议 <x>），不支持团队派发——需对方升级到 v0.5.0+`）；组内调度组内**任一**节点 < 1.9.0 → 黄字提示列出落后节点名（不拦提交）
  - **hub 门**（§5.1，权威兜底）：studio 闸数据滞后/绕过时由 hub 拒或排除候选池——旧 studio 节点不可能接到 team 任务
- **成员覆盖预检（本地零 IPC）**：团队模式下，指定节点 → 校验名单 ⊆ 本地镜像 workspace 成员名（镜像在本地可查），缺谁列谁（黄字，不拦——目标可能本地自建了同名成员）；组内调度 → 组员未全部与本地互为镜像 → 黄字列节点名
- **capability 数据源**：`routingPrecheck`（hub RPC）返回值扩展 `nodeCaps: Array<{ nodeId, name, protoVer }>`；hello 已带 protoVer，hub 汇聚即可

### 5.5 UI 预览门禁

`CreateTaskDialog` 执行方式区 + 预检黄字形态 = P1 变更：实现前出 `.omo/previews/m5.3-delegation-team.html` 静态预览（含单 agent / 团队协作两态 + 指定节点/组内调度 × 预检命中/未命中组合），用户确认后落码。

## 6. F2 镜像模型自动配平

### 6.1 快照段（builder）

`SnapshotAgentMember` 新增可选字段：

```ts
modelBinding?: {
  providerName: string;              // 源 provider 用户名（对齐键①）
  platform: 'openai' | 'anthropic';  // 协议族（对齐键②）
  modelName: string;                 // 模型 id（对齐键）
};
```

- 收集：源 def 有 `modelProviderId` 时，经 `getProvider` 解析 name/platform + `def.modelName`；源未配置 → 不带段
- custom YAML 仍不带模型（既有红线不动）；段挂 member 条目，slug 引用行与 custom 行同构
- 红线：零 key（延续 modelBinding 全局段先例）

### 6.2 配平链（applier，只补空）

def 在目标落地（新建或复用）后，若 `!def.modelProviderId`：

1. 目标 provider 中 `name === providerName` 且其 `provider_models` 含 `modelName` → 绑定（该 provider id + modelName）；同名多个 provider → isDefault 优先、次按创建序取首
2. 否则 provider 中 `platform === platform` 且 `provider_models` 含 `modelName` → 绑定（isDefault 优先、次按创建序取首）
3. 否则目标 `defaultChatModel`（全局设置，镜像全局段已对齐）存在 → 绑定
4. 否则保持未配置（spawn 时现有人话报错兜底：「请到 Agent 库配置」）

- **只补空**：`existing.modelProviderId` 非空一律不动（D4 自愈① 既有行为保持，本链只在其 else 分支生效）
- 配平写 `agent_definitions`（目标全局库 def 级——模型配置本就在 def 上）；不写 provider 表、不增补 `provider_models` 条目
- 模型名精确匹配（大小写敏感）

### 6.3 交互时点

配平只在镜像 apply 时跑（`applyMirrorSnapshot` 成员重建段内）；不对存量做追溯扫描——已有镜像的空壳 def 由**下一次镜像**（组同步/手动重镜）补齐。

## 7. 错误处理与边界

| 场景 | 行为 |
|---|---|
| hub 收到非法 team 段 | bad_request 整包拒（不剥除） |
| 接收端成员缺失 | decline + 人话名单；任务在派发方保留待处理（现有状态机） |
| 接收端 leader 解析成功但成员失败 | 同上 decline（leader 单独在场无意义） |
| 目标节点协议过旧 | 指定节点拒提交；组内黄字提示 + 派到旧节点由 hub 校验拒 |
| 快照 modelBinding 全 miss | def 保持未配置，spawn 人话报错（现状） |
| 团队任务运行中成员被删（目标侧） | dispatch 快照 spawn 时定型，运行不受影响（快照语义） |
| team 与 agentSlug 同场 | 派发闸前置拒（UI 互斥）+ hub 兜底拒 |

## 8. 测试策略

**hub（332 基线 + 新增）**：team 段合法/非法矩阵（0 leader、2 leader、1 成员、9 成员、名超长、与 agentSlug 互斥）、assigned 事件透传、routingPrecheck nodeCaps。

**studio 主进程单测**：
- runner：team 全解析建会（成员/leader 标记正确）、缺一 decline 名单正确、leader mention 正确
- createDelegatedSession 多成员扩展 + 单成员回归
- 配平链四级 × 已配置不动 × 同名 provider 优先序 × defaultChatModel 缺省
- snapshot builder/applier 回路：modelBinding 收集（源未配置不带段）+ 只补空（目标已配保留）
- 派发闸：协议门（指定节点拒/组内提示）、互斥校验

**renderer 单测**：CreateTaskDialog 执行方式两态、团队下拉展开快照、预检黄字渲染、单 agent 默认态回归。

**e2e（hub-distribution 新场景）**：A 团队派发指定节点 → B 多成员会话 + leader dispatch 跑通；缺成员场景 declined 带名单；镜像配平场景（B 侧空壳 def 镜像后可 spawn）。

**回归锁**：单 agent 外派全链零变化（现有 e2e 场景不动）；无 team 段旧 payload。
