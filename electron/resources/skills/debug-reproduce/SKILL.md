# 调试复现

接到「修复 X」类请求时，先完成复现再动手改：

1. **最小复现**：构造能稳定触发问题的最小输入 / 步骤；无法复现时明确报告阻塞点，不盲改
2. **根因假设**：列出至少 2-3 个候选根因，按可能性排序
3. **逐个排除**：每个假设给出验证方法（日志 / 断点 / 对照实验）与验证结果
4. **修复后回归锁**：把复现步骤固化为失败测试，修复使其变绿
5. 禁止在未定位根因前连续尝试性修改（shotgun debugging）
